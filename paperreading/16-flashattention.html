这篇论文在说什么

第 1 期讲过，Transformer 的核心是注意力：每个字都要看一遍所有的字，给每个字打一个分数。如果一段话有 N 个字，就要算 N×N 个分数。N=4096 时，就是约 1680 万个分数，还要反复用到它们。

这让 GPU（专门做大量计算的芯片）又慢又费内存。此前很多人想办法少算一点，比如只看一部分字，可结果往往是计算次数少了，时间却没怎么少。2022 年，斯坦福的 Tri Dao 等人指出了一个被忽视的事实：真正慢的不是计算，而是搬数据。

他们的 FlashAttention 一个分数都不少算，结果和原来完全一样，却快了几倍，内存也省了最多 20 倍。今天你用的大模型，训练和运行时基本都用它或它的后代。

旧方法的问题：书桌太小，图书馆太远

生活中的类比

你在写作业，手边有一张很小的书桌，一旦要查资料，就得跑去图书馆拿书。你写字其实很快，但大部分时间都花在来回跑上。这就是 GPU 的处境。

两个名词解释一下：

HBM
显卡上的大容量内存，能放几十 GB，相当于图书馆。
SRAM
紧贴计算单元的小内存，每块只有 192KB，但快得多，相当于书桌。
IO
在两者之间搬数据的操作。算法里读写 HBM 的次数越多，就越慢。

旧的注意力要把 N×N 的表全存到图书馆里，算 softmax 的时候还要读出来，训练更新的时候还要再读一次。表这么大，书桌根本放不下，于是时间都花在跑腿上了。

核心思想：一块一块算，算完就丢

论文用了两个办法，合起来就是一句话：每次只把小块放到书桌上算，算完只留结果，表本身不存。

  • 切块（tiling）：把大表切成书桌放得下的小块，一块一块算。
  • 重算（recomputation）：训练时需要“倒回去”更新。旧方法要把表存着备用；新方法不存，到时候再一块块算一遍。听起来很浪费，其实重算比跑图书馆还快。

这里有个看起来过不去的难题：softmax。

关键难题：softmax 能分块算吗

softmax 是注意力的最后一步，作用是把一排分数变成加起来等于 1 的比例（类似百分比）。它的公式是：

pi = esi / ( es1 + es2 + … + esn )
si
第 i 个字的分数，可以是任何数。
ex
一个约等于 2.718 的数的 x 次方。它有个好处：结果永远是正数，而且分数高的会被放大。
分母
把所有数加起来，这样比例之和才等于 1。
用 3 个数算一遍
  1. 分数是 1、2、0
  2. e¹ ≈ 2.72，e² ≈ 7.39，e⁰ = 1
  3. 总和 = 2.72 + 7.39 + 1 = 11.11
  4. 比例：2.72÷11.11 ≈ 24%，7.39÷11.11 ≈ 67%，1÷11.11 ≈ 9%
  5. 检查：24% + 67% + 9% = 100%

问题来了：分母要用到所有分数。可是分块时，书桌上只有一部分分数，怎么算？

答案是只记两个数，就能边走边更新。为了防止 e 的乘方太大而溢出，实际中先减去最大值：

m = 目前见过的最大分数
l = 把见过的分数都减去 m 后，e 的乘方之和
为什么这样可以

就像计算全班的平均分，不用把所有人的卷子都摊在桌上。只要记住“目前的总分”和“目前的人数”，来一张卷子更新一次。m 和 l 就是这两个小本本上的数字。

来了一块新的分数（这块的最大值 m₂、总和 l₂），和之前的 m₁、l₁ 合并：

m = max(m₁, m₂)
l = em₁−m · l₁ + em₂−m · l₂

第二行的意思是：之前的总和是相对 m₁ 算的，现在标准变成了 m，所以要乘一个换算系数。这和把不同单位的钱换算成同一种货币再相加是一个道理。

动手试试：分块算 softmax，和整张一起算结果一样吗

下面有 8 个分数，每次只能看 2 个（书桌只放得下这么多）。点“看下一块”，观察 m 和 l 怎么更新。全部看完后，和一次算完的结果对照。

为了确认这不是巧合，我也用 16 个随机分数实测了：把它们分成每块 1、2、3、4、8 个，分块结果和一次算完的结果，最大差距只有约 1e-16，也就是计算机的舍入误差。这也是论文所谓“exact”（完全精确）的含义。

省了多少

整个算法：外层一块块把 K、V 拿到书桌上，内层一块块拿 Q，算分数、更新 m 和 l、累加结果，最后只把结果写回图书馆。整个过程没有产生过一张完整的 N×N 表。

跑图书馆的次数可以这样估算：

方法读写 HBM 的次数
旧方法约 N·d + N²
FlashAttention约 N²·d² / M
N
序列长度（字数）
d
每个注意力头的维度，一般是 64 到 128
M
书桌（SRAM）的大小

M 在分母上，书桌越大跑得越少，很符合直觉。论文说实际上能少跑最多 9 倍，还证明了在 N²d²/M 这个量级上不可能再改进，也就是说这个方法已经接近极限了。

实际效果

  • 注意力这一步本身：GPT-2 上最多快 7.6 倍。
  • BERT-large 比赛成绩：17.4 分钟，比 NVIDIA 的 MLPerf 记录（20.0 分钟）快约 15%。
  • 内存：最多省 20 倍。
  • 能读更长的文章：病历任务 MIMIC-III，从 512 字到 16K 字，F1 从 52.8 涨到 57.1；法律任务 ECtHR 从 72.2 涨到 80.7。
  • 第一次做到：在 Path-X（16K 长度）任务上，它是第一个超过随机水平的 Transformer。

影响和局限

影响：几乎所有主流深度学习框架后来都集成了它，PyTorch 也有官方实现。它也改变了研究者的想法：优化时不能只数加减乘除的次数，还要算搬数据的代价。第 12、15 期那些训练得起的模型，背后都靠这类技术。Tri Dao 后来继续做了 FlashAttention-2、3，还是第 23 期 Mamba 的作者之一。

局限：

  • 计算量还是 N²。它只减少搬数据，不减少计算。序列特别长时还是贵，这是第 23 期 Mamba 要解决的问题。
  • 只有 GPU 才这么明显。这种优化针对 GPU 的内存结构。树莓派这样的 CPU 结构不同，效果不能直接套用。
  • 重算要小心随机数。dropout 的随机结果必须和第一次一样，论文的办法是保存随机种子。

和你的机器人的关系：你在 spark 上用 vLLM 跑模型时，底层多半已经在用 FlashAttention 这类技术了。这条思路在机器人控制上也有用：循环变慢时，先看是不是在反复搬大块数据（比如图像拷贝），不一定是计算本身的问题。

一句话总结：书桌小就一块块算，算完就丢。一个分数都不少算，也能快好几倍。
