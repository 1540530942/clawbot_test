Toolformer：模型自己学会用工具Toolformer: Language Models Can Teach Themselves to Use Tools

大模型能写诗，却算不对 27 × 14，也不知道今天几号。给它工具最直接，但以前要么要大量人工标注，要么只在特定任务上生效。这篇论文的想法很漂亮：让模型自己在语料里猜哪里该调用工具，真的去调用，再看结果是否帮它更好地预测后面的词；有帮助的调用留下来，用来微调模型。没有人告诉它什么时候该用，判断标准就是它自己的损失。

自己决定查不查字典

做完形填空的学生

一个学生做完形填空，每道题前都可以查一下工具书。怎样教他什么时候该查？老师不必一题题指导，可以这样：他先随手查一些；查到的内容如果让后面的句子更容易猜，就算有用。把有用的记录下来当成范文，他照着范文练，就自然学会在合适的地方查字典。

比喻是我们编的。关键是“有用”的定义不来自人，而来自学生自己的猜题成绩。

三步：采样、执行、过滤

每个 API 调用是文本：<API> a(i) → r </API>。实际就用 “[”“]”“->” 表示，不改词表。

  1. 采样：给 M 一段提示，让它给文本 x 加调用（见下面的提示）。计算每个位置 i 开始调用的概率 pi = pM(<API> | P(x), x1:i−1)。保留 pi > τs 的前 k 个位置（默认 τs = 0.05，k = 5），每个位置采样最多 m = 5 个调用。
  2. 执行：真的去跑工具，结果也是文本。
  3. 过滤：下一节的公式。
问答工具的提示（节选）

Your task is to add calls to a Question Answering API to a piece of text. … Input: Joe Biden was born in Scranton, Pennsylvania. Output: Joe Biden was born in [QA("Where was Joe Biden born?")] Scranton, [QA("In which state is Scranton?")] Pennsylvania. … Input: x Output:

每个工具只需要几个这样的例子，靠 GPT-J 的少样本能力生成大量候选。

过滤公式

Li(z) = − Σj=in wj−i log pM(xj | z, x1:j−1) Li+ = Li(e(ci, ri))，　Li− = min( Li(ε), Li(e(ci, ε)) ) 保留调用，如果 Li− − Li+ ≥ τf
wt
距离权重：w̃t = max(0, 1 − 0.2 t) 再归一化。所以只看后面 5 个词，要求工具结果立刻有用。
L⁺
给了调用和结果后的损失。
L⁻
没有调用，或者只有调用没有结果，两者取小。这样保证是结果帮了忙。
τf
阈值。默认 1.0；计算器、翻译数据少，用 0.5。
算一个
  1. 文本：“The Nile has an approximate length of 6,853 km”。模型在 “of” 之后本来不太确定。
  2. 没有调用：后 5 个词加权损失 L(ε) = 5.2；只有调用没有结果：L = 4.9。L⁻ = 4.9。（这两个数是我们假设的）
  3. 给了 “→ 6,853 km”：L⁺ = 2.82。
  4. 差 2.08 ≥ 1，保留。论文表 10 里这个例子的实际差值正是 2.08。

一个容易忽略的细节（脚注 3）：过滤时把调用放在文本开头作为前缀，而不是插入到位置 i，因为这时 M 还没见过带调用的文本，插入会打断语流。

微调和推理

把通过过滤的调用插回原文：x* = x1:i−1, e(ci, ri), xi:n。除了插入的调用，内容和原语料完全一样，所以模型不会丢失能力。用普通语言模型目标微调（批 128，学习率 10⁻⁵，每种 API 最多 2.5 万条，8 块 A100）。

推理：照常生成，一旦生成 “→”，暂停，调工具，把结果和 “</API>” 接上继续。

怎么读这张表
  1. k = 1（普通贪心）时，T-REx 只有 40.3% 调用，WebQS 只有 8.5%，WebQS 几乎没有提升（18.9 到 19.3）。
  2. k = 1 时模型有一定“校准”：它不调用的那些题，本来就做得不错（44.3 高于平均 34.9）。
  3. k 变大，调用率上升，总分上升，但校准消失（不调用的那些题只有 22.5）。

表 10 看质量：差值大的调用通常有用（比如查尼罗河长度），差值小或负的通常没用（85 / 23，“Who was last time I was with?”）。也有例外：“Fast train success” 查到一首歌，差值 0.92，没用却过了 0.5 的阈值。作者认为一点噪声反而让模型不盲从。

读结果时要注意的地方

  • “自己决定”的程度：论文强调模型自主决定，但 98–100% 的调用率依赖 k = 10 的强制放宽。k = 1 时远没有这么高。
  • 评分宽松：LAMA 看前 5 个词里有没有答案；问答看前 20 个词；数学取第一个数字。GPT-3 也按此评分，公平，但绝对数字不要和其他论文比。
  • 工具里的另一个大模型：问答工具 Atlas-xxl 本身就是一个强大的系统。LAMA 的胜利有相当部分是 Atlas 的成绩。
  • 按任务禁用工具：LAMA 禁维基，问答禁 QA。这是为了防止“作弊”，但也说明这些数字不是“默认配置”。
  • “clearly outperforming GPT-3”只在部分任务：事实和数学胜；问答输，多语言不一定，见表。
  • 基线微调不足：OPT、GPT-3 未微调；GPT-3 用的是 davinci 原版。
  • 小笔误：§5 说“fourth example”，实际是表 10 的第 5 个。
  • 提示和启发式：号称自监督，每个工具还是要人写提示，计算器和翻译还要人写过滤规则。

亲手试：小模型学计算器

我们用 NumPy 走了一遍：语料里有两位数加减的句子，比如 cats 45 dogs 37 total 82 .（减法用 diff），还有不含计算的干扰句，以及“笔记句”：开头随便写个数或算式，后面的答案照抄它。笔记句是为了补上小模型缺的一样能力：读懂前文并照抄。GPT-J 见过海量网页，自然有这个能力，我们的小模型只能这样教，但笔记句里从不出现 “[ calc … → 结果 ]” 这种调用的完整格式。过滤公式和权重都和论文一样，结果用 τf = 0.5（论文给计算器用的值）。最大的差别：小模型没有少样本能力，候选调用由随机模板生成（随机位置、随机算式，七成概率用对的两个数），不是模型自己写的。预训练 6000 步，微调 4000 步，2 个种子。这是玩具。完整脚本在这里。

这组结果怎么读（诚实版）：
  • 跑了五次才走通，前三次失败的原因都写在最后的小表里。第 1 次：模型读不懂开头的调用，τ = 1 时 45000 句里一条也没留下，脚本退出。第 2 次换成三位数，还是读不懂。我们的判断是：笔记句的开头总是同一个词，模型学的是“抄固定位置上的数”，调用一放在前面，位置就错开了（第 3 次改掉这一点后就读懂了，算是间接验证）。第 3 次让笔记的开头随机变化，模型才真的读得懂前缀（加法 100%、减法 100% 能照着前缀答对），但 τ = 1 太严，只留下几十条。第 4 次改用论文给计算器的 τ = 0.5。第 5 次用同样的种子重跑，结果逐项相同，只是为了多存一份模型和下面的调用统计。
  • 过滤确实在挑好调用。全部候选里只有约 11% 是“对的”（算式对、插在答案前面），τ = 0.5 通过的里面有 62%。τ = 2 时一条也不剩：两位数的答案只有两三个词，加权后损失最多也就降一点几。
  • 种子 1 是论文想要的故事。预训练模型自己算加法 35%、减法 10%。微调后用普通贪心（k = 1），减法有 74% 的题会调用，正确率到 51%；放宽到 k = 3，减法 97%。对照组只在原文上继续微调，减法只有 31%。干扰句几乎不调用（k = 3 时 0%）。
  • 但加法变差了。k = 3 时加法调用率 100%，正确率却只有 33%，不如不用工具的对照组 76%。统计表说明原因：它写的加号都对，但两个数只有 68 / 150 次抄对，减法是 146 / 150。我们猜是因为加法本来就有一部分会算，通过过滤的加法调用少，没练够写算式（没有单独验证）。
  • 种子 0 是反面：自己会算，就不学工具。它预训练后加法已经 100%，减法 53%。会算的题，调用帮不了忙，过不了过滤。微调后 k = 1 时加法从不调用，减法只有 21% 调用，成绩和禁用工具时差不多（减法 74% 对 77%）。强制 k = 10 时，150 道加法题里有 125 次连 “→” 都写不出来；减法调用写得出来，但只有 4 次照抄结果，其余还是自己算。正确率掉到加法 16%、减法 5%。
  • 这和论文的两个观察呼应：一是表 9，k 放大时调用率上去了，但不该调用的也调用了，校准变差；二是图 4，小模型用不好工具（我们这里是两个种子之间的差别，不是规模差别，不能直接对应）。同一个脚本只换随机种子就得到相反的结论，也说明这种玩具上两个种子远远不够。
  • 和论文不同的地方：候选调用不是模型自己写的；“读前文”的能力是我们特意教的；语料是我们编的四种句子。所以这里只能说明过滤公式在做什么，不能说明 Toolformer 的效果。

后来发生了什么

工作关系
函数调用、工具 API背景知识：2023 年起成为大模型产品的标配。但实际多由人写的工具说明和示范训练
ReAct 式智能体多轮、可链式调用。正好弥补 Toolformer 单次调用的局限
MCP 等协议背景知识：工具接入标准化

局限和争议

§7 论文自己列的：

  • 不能链式：调用彼此独立生成，训练数据里没有串联。
  • 不能交互：不能翻页、不能改写查询。
  • 对措辞敏感：决定是否调用受输入措辞影响大。
  • 低效：处理 100 多万文档，只得到几千条有用的计算器调用。
  • 不计成本：不考虑调用的计算开销。

此外，损失下降不等于真的正确：工具返回错误但句子碰巧被预测对，也可能通过（我们的推论）。

一页总结

  • 一个判据：L⁻ − L⁺ ≥ τf，结果帮助预测后面的词就留下。
  • 一个好处：内容不变，只是加了调用，所以能力不丢。
  • 一个放宽：k = 10，调用率靠它。
  • 一个结果：事实和数学大涨，问答仍输 GPT-3。
  • 一个局限：只能调用一次，不能串联。
