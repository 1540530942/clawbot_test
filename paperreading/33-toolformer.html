Toolformer：模型自学用计算器Toolformer: Language Models Can Teach Themselves to Use Tools

能写长文却算不对乘法，那就教模型用计算器。Toolformer 不靠人写示例，而是让模型自己试，只留下那些让下一个词更好猜的调用。67 亿参数的小模型配上工具，数学题上比 1750 亿的 GPT-3 高出近 3 倍。不过纯知识问答上，它还是输给了大模型。

这篇论文在说什么

第 6 期的 GPT-3 能写长文，却不一定能算对 3 位数乘法。可计算器一秒就能算好，为什么不让模型用计算器呢？第 17 期 ReAct 用提示教模型用工具，但需要人写示例。

2023 年初，Meta 的 Toolformer 换了个方式：让模型自己学会，什么时候、怎么调用工具。训练时不需要标注任何答案，只看加了工具后，下一个词是不是更好猜了。今天大模型的“函数调用”就有它的影子。

旧方法的问题

此前的工具用法要么是手写提示模板，要么要靠人工标注大量对话数据（比如 Rewrite 这类工作）。这样成本高，而且换个工具就要重来。

生活中的类比

你想教孩子什么时候查字典。一种方法是每次都站在旁边提醒。另一种方法是让他读一本书，遇到不认识的词时就试着查一下，如果查完这段话突然看懂了，他就知道这种时候值得查。Toolformer 用的就是第二种。

核心思想：看工具有没有帮助

论文的工具有 5 个：问答系统、计算器、维基百科搜索、翻译、日历。调用都写成文本，比如 [Calculator(400/1400)→0.29]，所以模型不需要改任何结构。

这里最关键的是第三步：如何判断一次调用有没有用。

数学：用损失判断好不好

模型猜下一个词，如果把握是 p，损失就是：

L = −ln(p)
p
模型给正确的下一个词的概率。
ln
自然对数。p=1 时 ln(p)=0，p 越小，−ln(p) 越大。

然后比较两种情况：

留下调用的条件：L⁻ − L⁺ ≥ τ
L⁺
把调用和结果都给模型时，接下来的词的损失。
L⁻
没有调用，或者有调用但没有结果，两者中较低的损失。
τ
门槛。论文默认 1.0；计算器和翻译是 0.5。
句子：“……400 人（即 29%）通过”，下一个词是 29%
  1. 不调用：p = 0.05，L⁻ = −ln(0.05) ≈ 3.00
  2. 调用计算器：p = 0.80，L⁺ = −ln(0.80) ≈ 0.22
  3. 差 = 2.78 ≥ 1，留下

为什么 L⁻ 要比较两种情况？因为如果只是写下“[Calculator(400/1400)→”就有帮助，而结果并没有带来额外好处，那么工具本身就不是关键，这条也要删掉。

动手试试：这个调用该不该留下

下一个词是“29%”。拖动两个概率：不调用时模型猜中的把握，和调用后的把握。差距够大才留下（阈值 τ=1，来自论文的默认值）。

实际效果

日期类题目 Dateset 的差距最夸张，27.3 对 0.8，因为模型本身不可能知道今天的日期，日历工具用了 54.8%。MLQA（多语言问答）上它并没有稳定超过原模型。

也没有明显的代价：不用工具时，语言能力基本不变（CCNet 困惑度 10.5 对 10.6）。

影响和局限

影响：后来工具调用几乎成了大模型的标配，但做法不同，今天多半靠人写的数据和强化学习。不过“文本里写调用，交给外部执行，结果再写回来”这一格式留了下来。

局限（论文列出）：

  • 工具不能串联。不能用一个工具的结果接着调用另一个。
  • 不能交互。搜索结果不好，也不能换个词再搜。这正好是第 17 期 ReAct 擅长的。
  • 对措辞敏感。问法变一下，可能就不调用了。
  • 效率很低。从 100 多万篇文档里才找到几千个有用的计算器调用。
  • 不考虑代价。它不知道一次调用要花钱、花时间。对机器人来说这尤其重要。

和你的机器人的关系：“有帮助才留下”这条思路可以用来检查你的工具集：记录 llm_manager 每次调用工具后，规划结果是否变好，没用的工具就从提示里删掉。这能减少模型混淆，也能省 token。代价问题要自己加：调用摄像头和转动底盘的成本差很多。

一句话总结：让模型在读书时自己试着用工具，只保留那些真正让它猜得更准的调用。
