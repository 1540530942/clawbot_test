序列到序列：把一句话压成一个向量Sequence to Sequence Learning with Neural Networks

2014 年以前，主流翻译系统是一大堆分开调的零件。这篇论文用两个 LSTM 端到端解决：一个读，把整句压成 8000 个数；一个写，从这 8000 个数念出译文。它几乎不假设语言的任何结构，却第一次在大规模翻译任务上明显赢过了短语统计系统。论文还发现一个连作者自己也说不清完整原因的小技巧：把原句倒过来读，成绩猛涨。

听完再说的翻译

一位不许记笔记的口译员

会议上，发言人说一句，口译员要听完整句，不许记笔记，也不许回头再听，然后译出来。短句不难，长句就要把全句的意思都装进脑子。这就是序列到序列模型。

这位口译员发现一个怪招：让发言人把句子倒着念。于是最后听到的就是句子开头，马上就要译的也是句子开头，起步容易多了。起步一稳，后面也好了。

听起来很荒唐，但论文报告的成绩确实因此大涨。比喻是我们编的，只帮助理解。

定长的麻烦

普通深度网络要求输入和输出的大小固定。图片可以缩放到统一大小，句子不行。普通 RNN 能处理变长，但要求输入和输出一一对应：

ht = sigm(Whx xt + Whh ht−1)，　yt = Wyh ht

翻译的麻烦是：长度不一样，顺序也不一样。最简单的想法就是两步：先读完，再说。读完和说之间隔得很远，这就要求能记很久。

为什么普通 RNN 记不住（背景知识，不是本文推导）
  1. 误差每往回传一步，大约要乘一个系数。
  2. 如果系数是 0.9，传 50 步：0.950 ≈ 0.005，几乎消失。
  3. 如果系数是 1.1，传 50 步：1.150 ≈ 117，爆炸。
  4. LSTM 用门让信号走一条接近“乘 1”的路，所以能记得久；但仍可能爆炸，因此下面要做梯度裁剪。

模型

编码器读完，最后一步的隐藏状态就是句向量 v。解码器是一个语言模型，只是开始时带着 v：

p(y1, …, yT′ | x1, …, xT) = ∏t p(yt | v, y1, …, yt−1)
v
定长句向量。4 层，每层 1000 单元，状态和记忆各一份：4 × 1000 × 2 = 8000 个数。
<EOS>
句尾符号。靠它，模型能定义任意长度上的概率，也知道该在哪里停。

和最简单版本相比有三个不同：用两个不同的 LSTM（多一倍参数，也便于多语言）；用 4 层（每加一层困惑度降近 10%）；倒读原句。

核对 3.84 亿参数（我们自己算的）
  1. 输入词向量：160,000 × 1000 = 1.6 亿。输出词向量：80,000 × 1000 = 0.8 亿。softmax：1000 × 80,000 = 0.8 亿。合计 3.2 亿。
  2. 循环连接：每层 4 组门，每组权重 (1000 + 1000) × 1000 = 200 万，每层 800 万，4 层 3200 万。两个 LSTM 共 6400 万。
  3. 3.2 亿 + 0.64 亿 = 3.84 亿。和论文的数字一致。

倒读：论文最出名的技巧

只把原句倒过来，译文不倒。困惑度从 5.8 降到 4.7，BLEU 涨了约 4.5 分。

动手玩：倒读改变了什么

线连接原词和它的译词。拖动句子长度，看平均距离和最短距离。

算一下（论文只给结论，这是我们补的算式）
  1. 正读：第 i 个原词在位置 i，译词在位置 n + i，距离都是 n。
  2. 倒读：第 i 个原词在位置 n − i + 1，译词仍在 n + i，距离是 2i − 1，也就是 1、3、5……
  3. 平均距离：(1 + 3 + … + (2n − 1)) ÷ n = n² ÷ n = n。和正读一样。
  4. 变的是最短距离：从 n 变成 1。论文称之为最小时间差（minimal time lag）。

论文明确说“没有完整的解释”，只是相信这个机理：句首先建立联系，梯度容易传过来，“建立通信”。作者开始以为只会让句首更准，结果长句也变好了，所以猜测记忆使用得更好。还有一条猜想论文写明“没有验证”：普通 RNN 在倒读时也容易训练。下面的实验我们顺手试了一下。

这个技巧有局限。如果语言的词序相反（比如动词放在最后的语言），倒读未必仍然让“开头对开头”。论文只做英法翻译，这一点是我们的推论。

束搜索

训练最大化 log p(T|S)，翻译要找 argmax p(T|S)。所有句子都试一遍不可能，所以每步只留 B 个最好的开头。

宽度 B = 2 走一步
  1. 第一步，“猫”概率 0.6，“狗”0.3。留这两个。
  2. “猫”后接“追”0.5：0.30。“狗”后接“追”0.9：0.27。“猫”后接“咬”0.4：0.24。
  3. 留下“猫 追”和“狗 追”。贪心（B = 1）会直接丢掉“狗”，而“狗”这一支当时的第二步其实更有把握。
  4. 实现时把概率相乘改成 log 相加，防止数字太小。遇到 EOS 的候选就放入完成集。

论文的发现很实用：B = 1 已经不错，B = 2 拿到大部分好处。5 个模型、B = 2 比单个模型、B = 12 还便宜。

BLEU 怎么算

BLEU 比较译文和参考译文有多少连续词相同，分数 0 到 100。

BLEU = BP × exp( ¼ Σn=14 log pn )，　BP = min(1, e1 − 参考长度/译文长度)
算一个
  1. 参考：猫 追 狗 。译文：猫 追 鱼。
  2. 1 个词的片段：猫、追 对，鱼 错，p₁ = 2/3。2 个词的片段：“猫 追”对，“追 鱼”错，p₂ = 1/2。
  3. 3 个词：p₃ = 0/1。真实 BLEU 算的是整个语料的总数，所以单句算到 0 不要紧。
  4. BP 惩罚太短的译文，否则只翻译一个词就能满分精度。

这个分数要谨慎比较。论文脚注就说 BLEU 有多个版本：同一个最佳系统，用 multi-bleu.pl 得 37.0，官网写的是 35.8。

句向量里有什么

论文用 PCA 把隐藏状态投影到 2 维（图 2）。观察结果是：

  • 对词序敏感：主语和宾语互换后，句向量明显分开。只数词频的词袋模型做不到这一点。
  • 对主动被动不太敏感：同一件事换成被动说法，句向量仍然靠近。具体短语写在图里，我们没有看到图，所以这里不引用。

注意这里只有几个手选的短语，属于定性证据。下面的实验我们用距离做了一次定量检查。

读结果时要注意的地方

  • 同一组数字有两个版本：§3.3 说倒读把 BLEU 从 25.9 提到 30.6；表 1 里是 26.17 和 30.59。很可能一个来自另一次测量，但论文没有说明。
  • 赢的是基线，不是最好：34.81 没有赢当时最好的 37.0，论文自己也明确写了。
  • 靠集成：34.81 用 5 个模型，每个 3.84 亿参数。单个倒读模型是 30.59，低于基线。
  • 比较脚本：Bahdanau 的 28.45 也列在表里，但只是单个模型且配置不同，并不能直接说明倒读 LSTM 胜注意力。下一期会看到作者的结论恰好相反。
  • “长句不难”：和下一期的“长句明显退化”看似矛盾。两边单元（4 层 LSTM 和 1 层门控单元）、规模和 BLEU 分组都不同。
  • “几乎不假设结构”：倒读本身就利用了英法词序接近的先验。
  • 优化不算“容易”的全部：论文说“fairly easy to train”，但这是在 8 个 GPU、10 天，以及合适的初始化和裁剪下。

亲手试：玩具翻译

我们用 NumPy 手写了 LSTM 的反向传播（和数值微分对比过）。任务是自造语言：主动句 cat chases dog 和被动句 dog chased_by cat 都要译成 猫 追 狗，分句用 and 连接。初始化和裁剪 5 按论文；优化器换成了 Adam，因为我们试过 SGD 0.7，2000 步内学不动（步数比论文少太多）。训练最多 3 个分句，6000 步，测到 5 个分句，2 个种子。这是玩具，规模比论文小 3 个数量级以上。完整脚本在这里。

这组结果怎么读（诚实版）：
  • 6000 步时倒读更快学会：LSTM 的 3 分句全对率，倒读 78% 和 90%，正读 35% 和 88%。方向和论文一致，但种子 1 上差得很小。
  • 18000 步后这个差距消失：正读和倒读在训练范围内都是 100%。所以我们的玩具支持的是“倒读让优化变容易”（论文 §3.3 的说法），而不是“正读学不会”。我们的句子很短，论文的句子长得多，差距可能持续更久。这一点我们没有测。
  • 2 层的结果得看训练量：6000 步时 2 层反而差，BLEU 35 和 87，种子 0 没收敛。18000 步时和 1 层一样满分，所以这里看不出层数的好处。论文说深层明显更好（选 4 层）。我们的任务太简单，测不出来，这不是反驳。
  • LSTM 比普通 RNN 好很多：6000 步时普通 RNN 的 BLEU 只有 17 和 18，1 分句全对率也只有 15% 和 28%。普通 RNN 没有加到 18000 步，所以我们只能说它学得慢，不能说它永远学不会。
  • 状态太小确实不行：6000 步时 12 维只有 BLEU 10 和 12。同样没有加步数。
  • 束搜索影响小，集成影响大：6000 步时，2 层单模型从 B=1 到 B=12，BLEU 只从 35 到 38（种子 0）、87 到 86（种子 1）。而把这两个模型集成，B=1 就到 95，B=12 是 97，比它们各自都高。其中一个模型没收敛，集成还是有帮助。论文也说 B=1 已经不错，B=2 拿到大部分好处；集成也是它的主要手段（单模型 30.59，5 模型 34.81）。模型学好以后（18000 步），训练范围内 B=1 已是 100，没有提升空间。
  • 没见过的长度几乎全错：训练最多 3 分句，18000 步后测 4 分句，全对率倒读 10% 和 0%，正读 0% 和 2%。定长向量在没见过的长度上基本没有外推能力，这为下一期的注意力留下了动机（注意力在没见过的长度上也不行，详见下一期）。
只有 2 个种子，这是人造规则语言，规模比论文小 3 个数量级以上。
动手玩：真实模型 + 束搜索

这是实验里训练 18000 步的 2 层倒读 LSTM（48 维，种子 0），完全在你的浏览器里运行。可以写主动句，也可以写被动句（动词加 _by）；词表外的词会提示。多个分句用 and 连接。

“编码器—解码器”这个框架留下来了，也推广到图像描述、语音等。倒读技巧反而随着注意力普及而淡出（背景知识）。Sutskever 的结论“足够大的网络加足够的数据”，和后面的规模定律可以连起来看，这种联系是我们的解读。

局限和争议

  • 定长向量：8000 个数装任意长的句子。下一篇论文认为这是瓶颈。
  • 生僻词：词表外全变 UNK，人名只能丢。
  • 慢：循环无法并行，一个 C++ GPU 每秒只有 1700 词。
  • 倒读的解释：作者自认没有完整解释。
  • 只有英法：论文预期在其他序列问题上也好，但这里没有实验。

一页总结

  • 一个结构：读，压成向量；写。
  • 一个技巧：倒读。平均距离不变，最短距离从 n 到 1。
  • 一组数字：单模型 30.59，5 模型 34.81，基线 33.30，当时最好 37.0。
  • 一个实用结论：束宽 2 拿到大部分好处。
