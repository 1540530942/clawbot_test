GPT-2：把任务也写成文本Language Models are Unsupervised Multitask Learners

GPT-2 把 GPT-1 的结构基本原样放大到 15 亿参数，换成从 Reddit 外链筛出来的 40GB 网页文本，然后完全不微调，只靠在输入里写明任务，就在 8 个语言建模数据集中的 7 个上刷新了纪录，并在阅读理解、摘要、翻译、问答上表现出了能力。它第一次把“语言模型本身就是多任务学习者”作为主张提了出来，提示词、规模化和分阶段发布这些后来的重要话题都从这里开始。

它要解决什么问题

GPT-1 和 BERT 之后，“预训练 + 微调”成了标准做法。但它有一个绕不开的前提：每个任务都需要一份标注数据，并且要单独训练一份模型。这样得到的系统更像窄领域的专家：在训练分布上表现很好，换一个分布或者换一个任务就很脆弱。

当时另一条路是多任务学习，比如 McCann 等人的 decaNLP，把十个任务放到一个模型里一起训练。但多任务学习要取得泛化，需要非常多的（数据集，目标）组合，而每个组合都要人工构建，扩展起来很慢。

GPT-2 提的问题更激进：能不能不改参数、不改结构，一个模型零样本完成下游任务？GPT-1 论文最后那一节已经观察到，随着预训练进行，零样本成绩会稳步上升。GPT-2 就是把这个观察当作主线，把规模和数据都放大来验证。

核心思路

论文的第一个论点是概率建模层面的。单任务学习估计的是 p(output | input)；一个通用系统要做很多任务，应该估计 p(output | input, task)，也就是输出既取决于输入，也取决于要做什么任务。

以前的做法是在结构上把 task 表达出来（不同的头、不同的编码器）或者在训练算法上（元学习）。GPT-2 的观察是：task 本身也可以写成一段文本。“翻译成法语”、“总结一下”都是自然语言，可以和输入一起作为前缀交给语言模型。这样一来，p(output | input, task) 就只是语言模型已经在学的 p(下一段文本 | 前文) 的一个特例。

第二个论点是数据层面的。互联网文本里本来就散落着大量“任务示范”：有人在文章里先写英文再给出法语翻译，有人在长帖后面写 “TL;DR:” 加一句总结，有人写问答。如果语言模型足够大、数据足够多样，它为了把下一个词预测好，就不得不学会这些任务。论文的说法是：问题变成了我们能否在实践中把这个无监督目标优化到收敛。

为什么这个想法在 2019 年是反直觉的

当时主流的理解是：语言模型预训练提供“好的表示”，任务能力来自微调。GPT-2 反过来说，任务能力可以直接从语言建模里涌现出来，微调只是让它更好用。要支撑这个说法，必须同时满足两点：数据里要真的有足够多样的任务示范（所以要换数据），模型要大到能学会它们（所以要放大）。这就是 GPT-2 在工程上只做了两件事的原因。

WebText：数据怎么来的

GPT-1 的 BooksCorpus 只有小说，题材太窄，不可能包含翻译、问答这类示范。最直接的替代是 Common Crawl 这类全网爬取，但论文指出这类数据有严重的质量问题，大量内容难以理解。GPT-2 的折中是借用人的判断做过滤：

为什么删掉 Wikipedia？很多评测集（问答、语言建模）直接来自或大量引用 Wikipedia。删掉它是为了减少训练集和测试集重叠，否则零样本成绩会被高估。这个处理在 2019 年并不常见，后来关于数据污染的讨论基本都从这里延续下去。

karma 过滤的代价也很明显：它反映的是 Reddit 用户的兴趣和人群构成，而不是“质量”本身。模型卡里 OpenAI 自己也说，训练数据包含大量未经过滤的网络内容，远谈不上中立。

字节级 BPE

想在任意网页文本上计算概率，分词器就不能有“未知词”。可选的方案都有毛病：词级分词有大量 OOV；字节级（直接把 UTF-8 字节当 token）能覆盖一切，但序列太长，当时的字节级语言模型效果也不如词级；常规 BPE 在 Unicode 码点上做，光是基础词表就要超过 13 万个符号，还没开始合并就已经太大了。

GPT-2 的做法是在字节上做 BPE：基础词表只有 256 个字节，任何字符串都能表示；再通过合并常见字节序列把词表扩大到 50,257，让常见词是一个 token、罕见字符串退回到字节。

深入篇 · 一

字节级 BPE：算法与一次真实运行

BPE 训练本身很简单：从最小的符号开始，反复把“当前最常相邻出现的一对符号”合并成一个新符号，直到词表达到目标大小。GPT-2 的两处改动是：最小符号是字节而不是字符；合并之前先用一个正则表达式预分词，合并只在每段内部发生。论文里“不跨字符类别合并、空格除外”这条规则，在实现上就是这个正则。

bpe.py · 教学版字节级 BPE（本页实际运行）

"""字节级 BPE 训练（教学版）。预分词正则近似 GPT-2：Python re 没有 \\p{L}，用 [^\\W\\d_] 代替。"""
import re
from collections import Counter

PAT = re.compile(r"""'s|'t|'re|'ve|'m|'ll|'d| ?[^\W\d_]+| ?\d+| ?[^\s\w]+|\s+(?!\S)|\s+""")


def train_bpe(text, n_merges):
    # 1) 预分词：字母、数字、标点各成一段，空格贴在后面的词上。合并只发生在段内，
    #    这就是论文说的“不跨字符类别合并（空格除外）”。
    words = Counter(PAT.findall(text))
    # 2) 每段转成 UTF-8 字节序列：基础词表只有 256 个符号
    vocab = {tuple(bytes([b]) for b in w.encode("utf-8")): c for w, c in words.items()}
    merges = []
    for _ in range(n_merges):
        # 3) 按词频加权，统计所有相邻符号对
        pairs = Counter()
        for w, c in vocab.items():
            for a, b in zip(w, w[1:]):
                pairs[(a, b)] += c
        if not pairs:
            break
        (a, b), c = pairs.most_common(1)[0]
        merges.append((a, b, c))
        # 4) 把出现的 (a, b) 全部替换为新符号 a+b
        new = {}
        for w, cnt in vocab.items():
            i, t = 0, []
            while i < len(w):
                if i + 1 < len(w) and w[i] == a and w[i + 1] == b:
                    t.append(a + b); i += 2
                else:
                    t.append(w[i]); i += 1
            new[tuple(t)] = cnt
        vocab = new
    return merges, vocab


def show(bs):
    try:
        return bs.decode("utf-8")
    except UnicodeDecodeError:          # 半个汉字：显示为十六进制字节
        return "".join(f"<{x:02x}>" for x in bs)


if __name__ == "__main__":
    corpus = ("the robot turns left at the wall. the robot turns right at the door! "
              "the robot stops. does the robot stop? the robot stops at the red line. "
              "robots and rovers turn, stop, and turn again. the rover turns left; the robot turns right. "
              "机器人在墙前左转。机器人在门前右转。机器人停下。")
    print("预分词:", PAT.findall("the robot stops. does the robot stop? 机器人停下。"))
    merges, vocab = train_bpe(corpus, 30)
    for i, (a, b, c) in enumerate(merges, 1):
        print(f"{i:2d}. {show(a)!r:>22} + {show(b)!r:<10} (频次 {c}) -> {show(a + b)!r}")
    for w in vocab:
        s = b"".join(w).decode("utf-8")
        if s in ("the", " the", " robots", " rover", "机器人停下"):
            print(f"{s!r:>14} -> {[show(x) for x in w]}")

GPT-2 开源分词器里的正则使用 \p{L}（任意字母）和 \p{N}（任意数字），需要第三方 regex 库。这里用 Python 内置 re 的 [^\W\d_] 近似字母类，结构与原版相同。

这段输出里能看到字节级 BPE 的几个重要性质：

  • 空格是词的一部分。预分词把空格贴在后面的词上，所以 " the" 合并成了一个 token，而句首没有空格的 "the" 还是 t + he 两个 token。同一个词在句首和句中是不同的 token，这是 GPT 系列分词器的一个经典特点，写 prompt 时多一个或少一个空格都会改变模型看到的输入。
  • 标点不会粘在词上。stop? 被预分词切成 " stop" 和 "?"，所以不会出现论文说的 dog.、dog!、dog? 各占一个位置的浪费。
  • 常见词变成一个 token，罕见词退回到碎片。" robot" 出现 7 次，合并成一个 token；" robots" 变成 " robot" + "s"；只出现两次的 " rover" 还是 " ro"、v、e、r。
  • 中文按字节合并，可能切在半个字中间。“机”的 UTF-8 是 e6 9c ba 三个字节。合并第 13 步的 <ba><e5> 跨越了两个汉字的边界（“机”的末字节加下一个字的首字节）；最后学出来的长 token 是“机器人”加上下一个字的第一个字节。字节级 BPE 只看统计，不在乎字符边界，所以任何字符串都能表示，但切分结果对人来说未必有意义。

按 GPT-2 开源分词器的设定，50,257 = 256 个字节 + 50,000 次合并 + 1 个特殊的 <|endoftext|>（这一拆分本期未重新核实）。由于 WebText 以英文为主，词表中的中文合并很少，一个汉字常常要 1 到 3 个 token，同样长度的中文比英文占用更多上下文。

模型改动与规模

GPT-2 的结构“基本沿用 GPT-1”，只改了几处，但这几处都和“能把模型堆深”直接相关：

  • LayerNorm 前移（Pre-LN）。每个子层的输入先做 LayerNorm，再进 attention 或 FFN，残差直接相加，不再在相加之后归一化。
  • 最后加一层 LayerNorm。最后一个 block 之后再做一次归一化，因为 Pre-LN 下残差流本身从未被归一化过。
  • 残差层初始化按 1/√N 缩放，N 是残差层的数量。
  • 上下文从 512 扩到 1024，词表 50,257，batch 512。
为什么这几个改动要一起做

原文只说了改了什么，没有解释为什么。领读人的理解是：GPT-2 最大的模型有 48 层，是 GPT-1 的四倍。Post-LN 下，每一层的输出都要过一次 LayerNorm，梯度回传时要穿过很多层归一化，越深越难训，通常需要很小心的 warmup。Pre-LN 让残差通路变成一条从输入到输出的恒等“高速公路”，深层梯度更稳定。

代价是残差流本身从不被归一化，每过一个 block 就累加一次，层数越多数值越大，所以要在最后补一层 LayerNorm；同时把残差分支的初始化按 1/√N 缩小，让累加了 N 次之后的方差还在合理范围。这三件事是一个整体。后来的研究系统地证明了 Pre-LN 在深层 Transformer 上更易训练，今天几乎所有大模型都用 Pre-LN（或其变体 RMSNorm）。

深入篇 · 二

LayerNorm、残差与 1/√N：一次数值实验

图 5 和后面的解释框只讲了直觉。这一节把它算清楚，并用实际运行的实验验证。

残差流的方差会怎样增长

Pre-LN 下，第 l 个 block 之后的残差流可以写成 embedding 加上所有残差分支的输出之和：

xl = x0 + Σi=12l fi( LN(x·) ) # 每个 block 有 attention、FFN 两条分支

每个 fi 的输入都经过 LayerNorm，尺度固定，所以每条分支的输出方差大致是同一个常数 v。若各分支输出近似不相关，方差直接相加：

Var(xl) ≈ Var(x0) + 2l · v ⟹ std(xl) ∝ √l

48 层的 GPT-2 有 N = 96 条残差分支，最顶层的残差流尺度大约是第一层的 √96 ≈ 9.8 倍。把每条分支最后那个投影矩阵（attention 的 WO 和 FFN 的 Wproj）的初始值乘以 1/√N，分支输出方差变成 v/N：

Var(xl) ≈ Var(x0) + (2l / N) · v ≤ Var(x0) + v # 不论多少层，顶层都被限制在 v 量级

这就是“残差层初始化按 1/√N 缩放”的含义：让模型无论多深，初始时残差流的总尺度都差不多。nanoGPT 的实现是把这些投影层的初始化标准差设为 0.02/√(2·层数)，和这里的 N = 2L 一致。

三条曲线各说明一件事：

  • Post-LN（GPT-1）的前向尺度最“稳”，每层都是 1。但代价在反向：梯度要从输出一路穿过 2L 个 LayerNorm 才能到底层，每个 LayerNorm 都会按当前输入的尺度重新缩放梯度。层数一多，底层的梯度就变得不稳定，需要很小的学习率和更长的 warmup。
  • Pre-LN 不缩放：残差通路上没有任何归一化，梯度可以沿恒等路径直达底层，所以好训。但前向尺度随 √l 增长，顶层的 6.87 比底层大得多，后面几层的分支输出相对残差流越来越“小”，贡献被稀释。
  • Pre-LN + 1/√N：同时得到了“梯度直通”和“尺度可控”。顶层残差流仍然没有被归一化（0.68），所以在接输出层之前还需要一个最终 LayerNorm，否则 logits = x·WeT 的尺度会随残差流变化。这就是 GPT-2 三个改动是一个整体的原因。

这个实验只看初始化时的前向尺度，不涉及训练动态。关于 Post-LN 与 Pre-LN 训练稳定性的系统分析见后续研究；这里的解释是领读人的整理，原文只列出了改动。

几个值得细看的点：

  • LAMBADA 测的是长程依赖：要预测一段话的最后一个词，必须读懂前面好几句。困惑度从 99.8 降到 8.6，准确率从 59.23% 到 63.24%。不过 63.24% 是加了一个停用词过滤器之后的数字：模型常常给出合理的续写但不是一个“句末词”，过滤掉这种情况后才达到这个成绩，不加过滤是 52.66%。
  • CBT（儿童读物完形填空）：普通名词 93.3%、命名实体 89.05%，此前分别是 85.7% 和 82.3%。
  • 小数据集提升最大：WikiText-2、PTB 这些训练集小的数据集提升最明显，因为以前的模型受困于训练数据少，而 GPT-2 带着 40GB 的知识来。
  • 1BW 没赢：它是其中最大的数据集，而且做了句子级打乱，破坏了长程结构，GPT-2 最擅长的长上下文完全派不上用场。这和 GPT-1 论文不选 1B Word 的理由完全一致。

困惑度、BPB 与零样本评测的计算细节

几种指标如何换算

平均负对数似然 ℓ = −(1/n) Σ log p(xi | x<i) # 单位 nats/token 困惑度 PPL = eℓ 每 token 比特 ℓ / ln 2 每字节比特 BPB = (Σ 负对数似然, 以 bit 计) / 原文字节数 # enwik8 用 BPB，text8 用 BPC

困惑度是“按 token”计的，不同分词器切出的 token 数不同，困惑度就不能直接比。BPB 和 BPC 按原文的字节或字符归一化，与分词方式无关。这正是字节级 BPE 的另一个好处：GPT-2 可以在任何数据集的原始文本上直接算概率，再按该数据集要求的单位报告结果。

为什么还需要反分词器

很多传统语言建模数据集是预先分好词的，比如 PTB 风格的 don 't、( word )，这和 WebText 里的自然文本差别很大。GPT-2 为每个数据集写了可逆的反分词器，把这些人为痕迹还原成自然文本再打分。因为可逆，原数据集上的对数概率仍然可以精确计算。原文把这当作一种简单的领域适配，它带来了 2.5 到 5 的困惑度改善。这个细节说明，零样本评测的数字对预处理很敏感。

几乎所有任务都可以归结为两个原语：给续写打分（LAMBADA、CBT、Winograd）和生成续写（CoQA、摘要、翻译、问答）。下面是这两个原语的实现，接在第 3 期的模型代码后面：

mini_gpt.py · 零样本评测的两个原语

def score_continuation(p, ctx, cand, n_head, post_ln):
    """零样本打分：候选续写的平均 token 对数概率（GPT-1 的 RACE 启发式、GPT-2 的 CBT 做法）。"""
    ids = ctx + cand
    lp = log_softmax(forward(p, ids[:-1], n_head, post_ln))
    pos = np.arange(len(ctx) - 1, len(ids) - 1)          # 预测 cand 各 token 的位置
    return lp[pos, np.array(cand)].mean()


def sample_top_k(p, ids, n_new, k, n_head, post_ln, rng, T_max):
    """GPT-2 摘要用的 top-k 采样（论文取 k=2）。"""
    ids = list(ids)
    for _ in range(n_new):
        logits = forward(p, ids[-T_max:], n_head, post_ln)[-1]
        top = np.argsort(logits)[-k:]
        probs = softmax(logits[top])
        ids.append(int(rng.choice(top, p=probs)))
    return ids

为什么用“平均”对数概率而不是总和

总对数概率随候选长度单调下降（每多一个 token 就多乘一个小于 1 的概率），直接比总和会系统性地偏向短答案。按 token 数取平均是最简单的长度归一化。GPT-1 的 RACE 启发式、GPT-2 的多项打分都用了这个做法，后来 GPT-3 的多选评测也基本沿用。

是记住了还是学会了

训练集来自互联网，测试集也大多来自互联网，一个自然的质疑是：GPT-2 是不是在测试时“背出了”训练时见过的内容？论文专门做了检查：用 Bloom filter 统计每个测试集中有多少 8-gram 也出现在 WebText 训练集里，并和每个测试集与它自己训练集的重叠做比较。

论文的结论比较克制：重叠带来的提升是“小但一致”的，不足以解释主要结果。个别情况确实存在，比如 CBT 测试集里的《丛林之书》也出现在 WebText 中。论文还观察到，WebText 训练集和留出集上的表现相近，并且都随模型变大而提升，于是给出一句后来被反复引用的结论：即使是 15 亿参数的模型，依然欠拟合 WebText。换句话说，还能继续放大。这句话几乎直接导向了一年后的 GPT-3 和 Scaling Laws。

分阶段发布

GPT-2 的影响力有一大半来自论文之外。2019 年 2 月 14 日，OpenAI 发布论文和博客时只放出了最小的模型，理由是担心大模型被用来大规模生成欺骗性、带偏见或侮辱性的文本，并称这是一次“负责任披露”的实验，他们自己也不确定这样做是否正确。

在 1.5B 发布时，OpenAI 公布了几条观察：

  • 他们训练的检测模型识别 1.5B GPT-2 生成文本的准确率约 95%，但他们自己认为这还不足以单独用于检测。
  • 康奈尔大学的合作者让人给生成文本的“可信度”打分，1.5B 模型得 6.91/10，774M 是 6.72，355M 是 6.07。模型越大，人越容易相信它写的东西。
  • 到那时为止，他们“没有看到强有力的滥用证据”。米德尔伯里国际研究学院的 CTEC 演示了把 GPT-2 微调后生成四种意识形态的宣传文本，但这只是能力演示，不是实际滥用记录。

这次发布在当时争议很大。一部分研究者认为扣下模型是在制造噱头，也违背了开放研究的惯例；另一部分人认为它开了一个先例，让“发布前评估风险”成为可讨论的事情。今天的模型卡、分级访问、发布前红队测试，都能在这次实验里找到起点。

放到树莓派 5 上

单条序列逐 token 生成时，每生成一个 token 都要把全部权重从内存读一遍，速度的上限主要由内存带宽决定：

tokens/s 上限 ≈ 有效内存带宽 B ÷ 权重字节数

深入篇 · 五

同期工作：decaNLP 与 BERT

工作怎么表达“任务”需要任务标注吗结构
decaNLP / MQAN（2018-06）把 10 个任务全部改写成“针对上下文回答问题”需要，10 个任务一起有监督训练一个多任务问答网络，没有任何任务专属模块或参数
BERT（2018-10）特殊 token + 每个任务一个输出层需要，逐任务微调Transformer encoder，双向
GPT-2（2019-02）任务描述和示例直接写在输入文本里不需要，零样本Transformer decoder，单向

decaNLP 与 BERT 的描述取自各自 arXiv 摘要页。

decaNLP 已经提出“用一个统一格式表达所有任务”，但它的统一格式是人工设计的问答模板，模型仍然要在这 10 个任务的标注数据上训练。GPT-2 把这一步推到极端：格式就是自然语言本身，训练数据就是网页，完全不用任务标注。论文在方法部分讨论多任务学习时引用了 McCann 等人的这项工作。

和 BERT 的关系更微妙。GPT-2 没有报告 GLUE，论文结尾承认还不清楚额外的数据和容量能否弥补单向表示相对 BERT 的低效。这场“理解任务上单向能否追上双向”的比较，在 GPT-2 里实际上被搁置了，直到 GPT-3 用规模和 few-shot 换了一个比较的维度。

影响与后续

直接的后继是 GPT-3（第 6 期）。GPT-2 最后的结论是“还在欠拟合”，GPT-3 的回应就是继续放大，并把图 2 里那种“上下文放几个示例”的做法正式命名为 in-context learning，系统地比较了 zero-shot、one-shot 和 few-shot。

Scaling Laws（第 7 期）把图 7 那种“规模越大越好”的观察变成了可预测的幂律曲线。GPT-2 是第一篇让人明确看到这种趋势、并把它当成主线叙事的论文。

工程层面，GPT-2 的很多设定成了默认值：Pre-LN 加最终 LayerNorm、字节级 BPE、残差初始化缩放。NVIDIA 的 Megatron-LM 以 GPT-2 的结构为基础做模型并行，把规模推到数十亿参数。由于 WebText 没有公开，社区复刻了 OpenWebText；karpathy 的 nanoGPT 至今仍以“在 OpenWebText 上复现 GPT-2 124M”作为标准示例。

局限与争议

  • 论文自己承认的：零样本“离可用还很远”。摘要只比随机强一点，英译法略差于查词典，开放问答 4.1%。论文的贡献是证明了方向，而不是给出可用系统。
  • 没回答单向还是双向。论文在结尾说打算在 decaNLP 和 GLUE 上做微调，因为不清楚额外的数据和容量能否弥补 BERT 已经展示的单向表示的低效。这个问题在 GPT-2 里没有结论。
  • 数据不公开，难以复现和审计。WebText 没有发布，外界只能复刻近似版本；数据中的偏见、版权、隐私都很难核查。模型卡明确说，不支持需要生成内容为真的用途，也不建议在没有偏见研究的情况下部署到与人交互的系统中。
  • 污染分析不完美。8-gram 重叠是一个粗略指标，改写过的内容、同一事实的不同表述都查不出来，后来的研究对基准污染的担忧只增不减。
  • 分阶段发布的效果有争议。完整模型发布后没有出现论文担心的大规模滥用，批评者认为风险被高估；支持者认为这本身就是实验结果的一部分。
  • “无监督多任务学习者”这个标题说得偏满。能力确实随规模出现，但大部分任务的绝对水平很低，真正可用的通用能力要等到更大的模型以及指令微调和 RLHF（第 14 期）。

和你的关系

任务即提示，这就是你的规划器接口。让 LLM 做机器人任务规划，本质上就是在估计 p(动作序列 | 传感器状态, 任务指令)。GPT-2 的经验是：零样本能力强烈依赖规模，小模型基本做不了。如果想在树莓派上本地跑一个小模型做规划，不要指望零样本，要么在上下文里给几组示范（图 2 的做法），要么在自己的任务数据上微调；需要真正零样本的开放任务交给云端大模型。

用置信度做端云分流。Natural Questions 那组数据（整体 4.1%，但最有把握的 1% 能到 63.1%）说明模型输出的概率本身是有信息的。端侧小模型可以先算一下自己的 log-prob 或候选动作之间的概率差，高置信直接本地执行，低置信再上传云端，这比固定规则切换更省带宽。

规模账先算清楚。按参数量粗算，GPT-2 124M 在 fp16 下权重约 0.25GB，1.5B 约 3.1GB，都放得进树莓派 5 的内存，但推理速度和发热需要实测。这四个规模也很适合当你端侧部署的基准模型：结构简单、实现多、量化工具链成熟。
