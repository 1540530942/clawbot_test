GPT-1：先学会说话，再学会做题Improving Language Understanding by Generative Pre-Training

这篇论文用一个 12 层的 Transformer decoder，先在 7000 多本书上做从左到右的语言建模，再加一个线性头、少量特殊 token 去微调下游任务，结果在 12 个数据集里的 9 个上超过了当时为各自任务专门设计的模型。它让“通用预训练 + 轻量适配”成了 NLP 的默认做法，GPT 这个名字和后来整条 decoder-only 路线都从这里开始。

它要解决什么问题

2018 年上半年，NLP 的状态可以概括为“预训练只预训练了一半”。word2vec、GloVe 迁移的是词向量，一个词不管在什么句子里都是同一个向量；ELMo 用双向 LSTM 语言模型产出上下文相关的表示，但用法是把这些表示当作额外特征喂给下游任务自己的模型，下游模型结构还得各自设计。ULMFiT（Howard & Ruder）和 Dai & Le 已经在做“预训练语言模型 + 整体微调”，但用的是 LSTM。

论文开头点出了两个悬而未决的问题。第一，用什么目标预训练，学到的表示最能迁移？当时语言建模、机器翻译、篇章连贯性等目标各有支持者。第二，怎么迁移？主流做法要么改模型结构，要么设计复杂的学习流程，要么加辅助目标，没有共识。

背后的现实约束是标注数据：大多数任务只有几千到几十万条标注样本，而无标注文本几乎取之不尽。谁能把无标注文本里的知识更完整地搬进下游任务，谁就赢。

核心思路

GPT-1 的答案是三个选择叠在一起：

  • 目标用最朴素的语言建模。给定前文预测下一个 token。不需要任何标注，数据可以无限扩。
  • 结构用 Transformer decoder。论文明确说，LSTM 方案把预测能力限制在较短的范围内，而 Transformer 的注意力能直接抓住更长距离的结构。
  • 迁移时几乎不改结构。整套预训练权重原样带进下游，只新增一个线性输出层和几个特殊 token 的 embedding；不同任务的结构化输入被“改写”成一条 token 序列，让同一个模型直接吃进去。

和 ELMo 的本质区别在于：ELMo 迁移的是特征，下游模型是新的；GPT-1 迁移的是整个网络，下游只多一层。和 ULMFiT 的区别在于骨干网络换成了 Transformer，并且有一套通用的输入改写方案，不需要为每个任务设计结构。

方法迁移什么骨干网络下游怎么适配
word2vec / GloVe词向量浅层任务模型从头设计
ELMo上下文表示（作特征）双向 LSTM任务模型从头设计，表示作为输入特征

技术细节

1. 预训练目标

给定无标注语料 𝒰 = {u₁, …, uₙ}，最大化标准的语言模型似然：

L₁(𝒰) = Σᵢ log P(uᵢ | ui−k, …, ui−1 ; Θ) # k 是上下文窗口，实际训练用 512 个 token 的连续片段

这个目标的好处是：它强迫模型同时学会语法、语义、常识和篇章结构，因为任何一种信息都可能帮助预测下一个词。坏处是它只看左边，这一点后面 BERT 会专门针对。

2. 模型：只有 decoder 的 Transformer

h₀ = U·We + Wp # token embedding + 可学习的位置 embedding h_l = transformer_block(hl−1), l = 1…12 P(u) = softmax(hn · WeT) # 输出层复用输入 embedding 矩阵

最后一行的 WeT 说明输出投影和输入 embedding 是同一个矩阵（weight tying）。原文没写“tied”这个词，但公式就是这个意思。这样做省一大块参数，也让“输入一个词”和“预测一个词”共享同一套词表示。

为什么只要 decoder？原始 Transformer 是为翻译设计的 encoder-decoder：encoder 读源语言，decoder 一边看 encoder 输出一边生成目标语言。语言建模没有“源序列”，所以 cross-attention 没有意义，encoder 也就不需要了。剩下的就是一叠带因果掩码的 self-attention 层。这个看似是“删减”的决定，后来成了 GPT 系列、LLaMA 乃至今天绝大多数大模型的骨架。

3. 训练配置

项预训练微调
优化器Adam，峰值 lr 2.5e-4lr 6.25e-5
学习率调度前 2000 步线性 warmup，之后余弦退火到 0前 0.2% 步 warmup，之后线性衰减
batch64 条 × 512 token32
轮数100 epochs大多数任务约 3 epochs
正则dropout 0.1分类头 dropout 0.1；辅助 LM 损失 λ = 0.5
文本处理ftfy 清洗，spaCy 分词，再做 BPE（40,000 次合并）同左

预训练结束时，语言模型在 BooksCorpus 上的 token 级困惑度是 18.4。微调几乎不调参：3 个 epoch、固定的学习率，这本身就是论文想传达的信息，适配应该是一件便宜的事。

4. 微调目标和辅助语言建模损失

给定带标签的数据集 𝒞，每条样本是 token 序列 x¹…xᵐ 和标签 y。输入跑完整个模型，取最后一层、最后一个位置的向量 hlm，乘上新加的 Wy：

P(y | x¹…xᵐ) = softmax(hlm · Wy) L₂(𝒞) = Σ log P(y | x¹…xᵐ) # 任务本身的损失 L₃(𝒞) = L₂(𝒞) + λ · L₁(𝒞), λ = 0.5 # 在任务数据上继续做语言建模
为什么微调时还要保留语言建模损失

论文给的理由有两个：提升泛化，加快收敛。直觉上，下游数据很少，只用 L₂ 训练，模型会很快“忘掉”预训练学到的东西去拟合标签；同时优化 L₁ 相当于一个正则项，把权重拉在“仍然是个好语言模型”的区域附近。

但后面的消融会显示，这个效果并不稳定：在大数据集上有帮助，在小数据集上反而略有损失。这种“微调时混入预训练目标防止遗忘”的思路后来反复出现，比如 RT-2 在机器人数据上微调时混入网页视觉问答数据（第 21 期会讲）。

5. 输入改写：把结构化输入压成一条序列

这是这篇论文最工程化、也最有影响的部分。问题是：语言模型只吃一条连续文本，可下游任务的输入可能是“前提 + 假设”、“两个句子”或者“文章 + 问题 + 四个候选答案”。以前的做法是在上面搭任务专属结构（比如句对之间的交互注意力），GPT-1 的做法是只改输入，不改模型：

  • 分类：直接在文本两端加 Start 和 Extract。
  • 蕴含：前提和假设之间插一个分隔符。
  • 相似度：两个句子没有天然顺序，所以 A$B 和 B$A 各跑一遍，最后一层的两个向量逐元素相加，再送进线性层。这样模型不会被迫学到一个和顺序有关的偏差。
  • 多选（问答、故事结尾判断）：把上下文（和问题）分别与每个候选答案拼起来，各自独立打一个分，再在候选之间做 softmax。
为什么不在上面搭任务专属结构

任务专属结构意味着大量新参数从零训练，而下游数据又少，这些新参数会成为瓶颈，也会削弱预训练表示的作用。把任务压成序列之后，“理解两个句子之间关系”这件事就交给了已经预训练好的 self-attention，因为在一条序列里，后一句的每个 token 本来就能注意到前一句。

代价是要为每类任务想好格式，而且格式一旦定了，模型只能学会那一种输入形状。GPT-2 和 GPT-3 把这一步推到极致：干脆用自然语言描述任务，连 Delim 和 Wy 都不要了。

把上面几步合起来，一次微调更新大概是这样（示意，非原文代码）：

# 以蕴含任务为例 tokens = [START] + premise + [DELIM] + hypothesis + [EXTRACT] h = transformer(tokens) # (len, 768)，12 层 y_hat = h[-1] @ W_y # 只用 Extract 位置的向量 lm = h[:-1] @ W_e.T # 同一套 embedding 做下一个词预测 loss = CE(y_hat, y) + 0.5 * CE(lm, tokens[1:])

6. 数据：为什么是 BooksCorpus

预训练语料是 BooksCorpus，包含 7000 多本未出版书籍。论文给出的关键理由是：书里有很长的连续文本，模型可以学习长距离依赖。作为对照，ELMo 用的 1B Word Benchmark 规模相近，但在句子级别被打乱了，长程结构被破坏了。对于一个上下文 512 的 Transformer，这个区别很大：打乱的句子没有跨句信息可学。原文没有给出 BooksCorpus 的 token 数。

深入篇 · 一

注意力与训练目标的数学

这一节把图 2 里每个方框背后的公式完整走一遍，并用实际运行的数值实验检查几个常被一笔带过的设计。符号约定：序列长度 T = 512，模型宽度 d = 768，头数 H = 12，每头维度 dh = d / H = 64，词表 V = 40,478（取自 Hugging Face 上 openai-gpt 的配置文件）。

1. 一个注意力头在算什么

设某一层的输入为 X ∈ ℝT×d（每行是一个位置的向量）。一个头先做三次线性投影，再做加权平均：

Q = X·WQ, K = X·WK, V = X·WV # W 都是 d × d_h = 768 × 64 S = Q·Kᵀ / √dh + M # S ∈ ℝ^{T×T}，S_ij 是位置 i 对位置 j 的打分 Mij = 0 (j ≤ i), −∞ (j > i) # 因果掩码，见图 3 A = softmax行(S) # 每行和为 1 head = A·V # ℝ^{T×d_h}

直观地说：Q 是“我在找什么”，K 是“我能提供什么”，Q·Kᵀ 给出每对位置的匹配度，softmax 把匹配度变成权重，再用权重对 V 求加权平均。掩码把 j > i 的打分设成 −∞，softmax 之后对应权重恰好为 0，所以位置 i 的输出只由位置 0…i 决定。

2. 为什么要除以 √dh

假设 q、k 的各分量独立、均值 0、方差 1（初始化附近大致如此）。点积 q·k = Σi=1d_h qiki 是 dh 个独立项之和，每项方差为 E[q²]E[k²] = 1，所以：

E[q·k] = 0, Var[q·k] = dh ⟹ std(q·k) = √dh = 8 # GPT-1 的 d_h = 64

打分的标准差达到 8 时，softmax 会极度尖锐，几乎变成 one-hot。softmax 的雅可比矩阵是 diag(a) − a·aᵀ，当 a 接近 one-hot 时它接近零矩阵，梯度几乎传不回 Q 和 K，注意力就学不动了。除以 √dh 恰好把方差拉回 1。

下面是在本页编写时实际跑的实验：随机采 2000 个 query、512 个 key（与 GPT-1 上下文相同），比较缩放前后的 softmax：

d_h除以 √d_h打分方差平均最大权重平均熵（nats）
16否15.910.4522.17
16是0.990.0285.74
64否63.910.7250.84
64是1.000.0275.74
128否128.070.8110.53
128是1.000.0275.74

512 个 key，均匀分布时最大权重为 1/512 ≈ 0.002，熵上限 ln 512 ≈ 6.24。高亮行是 GPT-1 的 d_h = 64。

不缩放时，dh = 64 的平均最大权重已到 0.72，熵只有 0.84 nats，说明注意力几乎只看一个位置；缩放后最大权重约 0.027，熵 5.74 nats，接近 512 个位置均匀分布的上限 ln 512 ≈ 6.24。也就是说，缩放让模型在训练开始时从“到处都看一点”出发，再慢慢学会聚焦，而不是一开始就被随机噪声锁死在某个位置上。

3. 多头：把 768 维切成 12 份

12 个头各自有 64 维的 Q、K、V，独立计算注意力，然后拼接回 768 维，再乘一个 WO ∈ ℝ768×768 混合：

MultiHead(X) = Concat(head₁, …, head₁₂) · WO

计算量和一个 768 维的单头基本一样（实现上 12 个头的 WQ、WK、WV 合成一个 768×2304 的矩阵一次算完），但它允许不同的头关注不同的东西：一个头盯上一个词，另一个头盯句首的主语，等等。代价是每个头只有 64 维，单个头的表达能力变小，这是“头数 × 头宽”的经典取舍。

4. 一次前向，512 个训练信号

因为有因果掩码，长度 512 的序列跑一次前向，就同时得到 511 个“根据前文预测下一个词”的预测，它们共享所有中间计算。按原文的 batch（64 条 × 512 token），每步约有 64 × 511 ≈ 3.3 万个监督信号。RNN 也能逐位置算损失，但必须按时间步串行；Transformer 的所有位置可以并行，这是它在 GPU 上训练快得多的根本原因，也是 GPT-1 能在 BooksCorpus 上跑 100 个 epoch 的前提。

5. 交叉熵、梯度和困惑度

对某个位置，设最后的 logits 为 z = h·WeT ∈ ℝV，正确的下一个词是 y。损失和它对 logits 的梯度是：

ℓ = −log softmax(z)y = −zy + log Σj ez_j ∂ℓ / ∂z = softmax(z) − onehot(y) # 预测分布减去真实分布

梯度形式非常干净：模型给正确词的概率越接近 1，梯度越小。由于输出层和输入 embedding 共享 We，每个词向量同时从“作为输入被读到”和“作为输出被预测”两个方向得到梯度，这对低频词尤其有帮助。

初始损失应该是多少？随机初始化时 logits 几乎全为 0，预测接近均匀分布，所以 ℓ ≈ ln V。对 GPT-1，ln 40,478 ≈ 10.61 nats。本页的 NumPy 实现在 V = 100 的随机模型上测得初始损失 4.607，与 ln 100 ≈ 4.605 一致，这是检查实现是否写对的最快办法。

困惑度就是平均损失的指数：PPL = exp(平均 ℓ)。GPT-1 在 BooksCorpus 上的 18.4 对应平均 ln 18.4 ≈ 2.91 nats，也就是约 4.20 bits/token。直观地说，模型平均相当于在 18.4 个等可能的候选里猜下一个词，而训练开始时是在 4 万个里猜。

6. LayerNorm 与 GELU

LN(x) = γ ⊙ (x − μ) / √(σ² + ε) + β # μ, σ² 在 768 维上求，ε = 1e-5 GELU(x) = x · Φ(x) ≈ 0.5x · (1 + tanh(√(2/π) · (x + 0.044715x³)))

GELU 可以理解为“按概率保留”的 ReLU：x 越大越可能原样通过，负值附近是平滑的而不是硬截断。GPT-1 较早在语言模型预训练中采用 GELU，之后 BERT 和 GPT-2 都沿用了它，再后来 LLaMA 一系换成了 SwiGLU。

下表跟着一个 batch（B 条序列）走一遍完整前向。读论文时把形状算清楚，是确认自己真正理解结构的最好办法：

输入token id(B, 512)
embeddingWe[ids] + Wp[0:512](B, 512, 768)

拆头切成 Q、K、V 再 reshape(B, 12, 512, 64) × 3

加权求和softmax(S) · V(B, 12, 512, 64)

输出h · WeT(B, 512, 40478)

注意“打分”那一行：每条序列、每层都要存一个 12 × 512 × 512 ≈ 315 万个元素的注意力矩阵，随长度平方增长。这就是早期模型上下文长度只有 512 的主要原因之一，也是第 16 期 FlashAttention 要解决的问题。

合计 116,534,784，四舍五入正好是维基百科给出的 117M。这个数字由公式算出，又在本页的 NumPy 实现里真正初始化一遍、数组元素逐个相加核对过，两者一致。几个值得注意的比例：

  • 每层 708 万参数，其中 FFN 占三分之二（472 万对 236 万）。FFN 的 8d² 大于注意力的 4d²，这个比例在后来几乎所有 Transformer 里都成立。
  • embedding 占 27%（3,109 万 / 1.17 亿）。如果输出层不和输入共享，还要再多 3,109 万，总量变成约 1.48 亿。在小模型里，词表是一笔很大的开销。
  • 微调新增的参数微不足道。三类 NLI（3 个标签）只新增 3 个特殊 token 的 embedding（3 × 768）和一个 768 × 3 的线性层加偏置，共 4,611 个参数，约为全模型的 0.004%。

算力账

按常用的近似，前向每个 token 的计算量约为 2N + 2·L·T·d FLOPs（N 是不含 embedding 的参数量，第二项是注意力打分），再加上输出层 2·V·d。代入 GPT-1：

N(非 embedding) = 85,054,464 前向 ≈ 2 × 85.05M + 2 × 12 × 512 × 768 ≈ 179.5 MFLOPs / token + 输出层 2 × 40,478 × 768 ≈ 62.2 MFLOPs ⟹ 约 0.24 GFLOPs / token 训练（前向 + 反向 ≈ 3 倍） ≈ 0.73 GFLOPs / token 每步 64 × 512 = 32,768 token ⟹ ≈ 2.4 × 10¹³ FLOPs / step

原文没有给出 BooksCorpus 的 token 数和总步数，所以无法可靠地算出总训练量，这里只算到每步。公式是领读人按常用近似计算的，不是原文数字。

从零实现：约 100 行 NumPy

为了让每个公式都能落到代码上，这里给出一个只依赖 NumPy 的 GPT 前向实现。post_ln=True 就是 GPT-1，post_ln=False 就是下一期要讲的 GPT-2，两者只差 forward 里的四行。代码在本页编写时实际运行过，下面的输出都是真实结果。它只做前向（没有反向传播和优化器），目的是读懂结构；真正训练请看延伸阅读里的 nanoGPT。

mini_gpt.py · 模型主体

"""最小 GPT 实现（NumPy，仅前向）。post_ln=True 是 GPT-1，False 是 GPT-2。"""
import numpy as np


def gelu(x):  # GPT 系列用的 tanh 近似
    return 0.5 * x * (1 + np.tanh(np.sqrt(2 / np.pi) * (x + 0.044715 * x ** 3)))


def layer_norm(x, g, b, eps=1e-5):
    mu = x.mean(-1, keepdims=True)
    var = x.var(-1, keepdims=True)
    return g * (x - mu) / np.sqrt(var + eps) + b


def softmax(z):
    z = z - z.max(-1, keepdims=True)  # 数值稳定
    e = np.exp(z)
    return e / e.sum(-1, keepdims=True)


def init_params(V, T, d, L, rng, post_ln):
    n = lambda *s: rng.normal(0, 0.02, s)
    N_res = 2 * L                       # 每个 block 两条残差分支
    s = 1.0 if post_ln else 1 / np.sqrt(N_res)   # GPT-2：残差投影按 1/√N 缩放
    blocks = []
    for _ in range(L):
        blocks.append(dict(
            w_qkv=n(d, 3 * d), b_qkv=np.zeros(3 * d),
            w_o=n(d, d) * s, b_o=np.zeros(d),
            w_fc=n(d, 4 * d), b_fc=np.zeros(4 * d),
            w_proj=n(4 * d, d) * s, b_proj=np.zeros(d),
            ln1_g=np.ones(d), ln1_b=np.zeros(d), ln2_g=np.ones(d), ln2_b=np.zeros(d)))
    p = dict(wte=n(V, d), wpe=n(T, d), blocks=blocks)
    if not post_ln:
        p.update(lnf_g=np.ones(d), lnf_b=np.zeros(d))  # GPT-2 的最终 LayerNorm
    return p


def attention(x, blk, n_head):
    T, d = x.shape
    hd = d // n_head
    q, k, v = np.split(x @ blk["w_qkv"] + blk["b_qkv"], 3, axis=-1)       # 各 (T, d)
    q, k, v = (a.reshape(T, n_head, hd).transpose(1, 0, 2) for a in (q, k, v))  # (H, T, hd)
    scores = q @ k.transpose(0, 2, 1) / np.sqrt(hd)                        # (H, T, T)
    mask = np.triu(np.ones((T, T), dtype=bool), k=1)                      # 上三角 = 未来
    scores = np.where(mask, -1e10, scores)
    out = softmax(scores) @ v                                             # (H, T, hd)
    out = out.transpose(1, 0, 2).reshape(T, d)
    return out @ blk["w_o"] + blk["b_o"]


def mlp(x, blk):
    return gelu(x @ blk["w_fc"] + blk["b_fc"]) @ blk["w_proj"] + blk["b_proj"]


def forward(p, ids, n_head, post_ln, return_hidden=False):
    T = len(ids)
    x = p["wte"][ids] + p["wpe"][:T]                     # h0 = U·We + Wp
    for blk in p["blocks"]:
        if post_ln:   # GPT-1：x = LN(x + Sublayer(x))
            x = layer_norm(x + attention(x, blk, n_head), blk["ln1_g"], blk["ln1_b"])
            x = layer_norm(x + mlp(x, blk), blk["ln2_g"], blk["ln2_b"])
        else:         # GPT-2：x = x + Sublayer(LN(x))
            x = x + attention(layer_norm(x, blk["ln1_g"], blk["ln1_b"]), blk, n_head)
            x = x + mlp(layer_norm(x, blk["ln2_g"], blk["ln2_b"]), blk)
    if not post_ln:
        x = layer_norm(x, p["lnf_g"], p["lnf_b"])
    logits = x @ p["wte"].T                              # 权重共享：P(u) = softmax(h · Weᵀ)
    return (logits, x) if return_hidden else logits


def log_softmax(z):
    z = z - z.max(-1, keepdims=True)
    return z - np.log(np.exp(z).sum(-1, keepdims=True))


def lm_loss(p, ids, n_head, post_ln):
    """L1：平均每个 token 的负对数似然（nats）。"""
    lp = log_softmax(forward(p, ids[:-1], n_head, post_ln))
    return -lp[np.arange(len(ids) - 1), ids[1:]].mean()

对照公式读几处关键行：

  • x = p["wte"][ids] + p["wpe"][:T] 就是 h₀ = U·We + Wp，U 是 one-hot，所以“矩阵乘”实际是查表。
  • np.triu(..., k=1) 取严格上三角作为掩码，对应图 3 里的 −∞ 区域。实现里用 −1e10 代替真正的 −inf，softmax 后效果相同，又避免 inf 参与运算产生 NaN。
  • logits = x @ p["wte"].T 就是 P(u) = softmax(hnWeT)，权重共享在这里只是复用同一个数组。
  • GPT-1 分支是 LN(x + Sublayer(x))，GPT-2 分支是 x + Sublayer(LN(x))，加上最后的 lnf。

mini_gpt.py · GPT-1 微调：输入改写、任务头与 L₃

# ---------- GPT-1 微调：输入改写 + 任务头 ----------
def make_inputs(kind, START, DELIM, EXTRACT, a, b=None, answers=None):
    """把结构化输入改写成一条或多条 token 序列（对应 GPT-1 图 1）。"""
    if kind == "classify":
        return [[START] + a + [EXTRACT]]
    if kind == "entail":                      # a = premise, b = hypothesis
        return [[START] + a + [DELIM] + b + [EXTRACT]]
    if kind == "similar":                     # 两个顺序都要
        return [[START] + a + [DELIM] + b + [EXTRACT], [START] + b + [DELIM] + a + [EXTRACT]]
    if kind == "choice":                      # a = context(+question)，每个答案一条
        return [[START] + a + [DELIM] + ans + [EXTRACT] for ans in answers]
    raise ValueError(kind)


def task_logits(p, kind, seqs, W_y, b_y, n_head):
    """取每条序列最后一个位置（Extract）的最后一层向量 h_l^m，接线性头。"""
    hs = [forward(p, s, n_head, post_ln=True, return_hidden=True)[1][-1] for s in seqs]
    if kind == "similar":
        return (hs[0] + hs[1]) @ W_y + b_y            # 逐元素相加后再线性层
    if kind == "choice":
        return np.array([h @ W_y + b_y for h in hs]).ravel()  # 每个候选一个标量，再在候选间 softmax
    return hs[0] @ W_y + b_y


def finetune_loss(p, kind, seqs, label, W_y, b_y, n_head, lam=0.5):
    """L3 = L2 + λ·L1。L1 在同一批任务序列上计算。"""
    z = task_logits(p, kind, seqs, W_y, b_y, n_head)
    L2 = -log_softmax(z)[label]
    L1 = np.mean([lm_loss(p, s, n_head, post_ln=True) for s in seqs])
    return L2 + lam * L1, L2, L1

把规模和成绩对照起来看，有一个清楚的规律：GPT-1 输掉的两个数据集（RTE 2,490 条、MRPC 3.7k 条）恰好是最小的两个。同样很小的 CoLA（8.5k）和 STS-B（5.7k）却赢了，区别在于任务类型：CoLA 判断语法、STS-B 判断语义相近，这些能力基本可以从语言建模里直接学到；RTE 和 MRPC 需要更细的逻辑和复述判断，几千条样本不够把预训练表示“对齐”到任务上。原文也是这么解释 RTE 的，并猜测多任务训练可能有帮助，但没有验证。

另一个规律：提升最大的 Story Cloze（+8.9）和 RACE（+5.7）都是多句推理，原文的说法是模型能够有效地处理长程上下文。这正是“Transformer + 连续长文本”这个组合的优势所在。

成绩总览

值得注意的几点：

  • 提升最大的是需要长上下文的任务。Story Cloze（从两个结尾里选出合理的故事结尾）提升 8.9 个点，RACE（初高中英语阅读理解）提升 5.7 个点。这两个任务都要求跨多个句子推理，正好对应“Transformer + 长篇连续文本”这套组合的长处。
  • 单模型赢了集成模型。MNLI 上 82.1 对 80.6，后者是 3 个模型的集成；SNLI 上 89.9 对 89.3，后者是 5 个模型的集成。
  • CoLA 从 35.0 到 45.4。CoLA 判断句子是否合乎语法，训练集小，几乎完全依赖预训练学到的语言知识。
  • 输掉的两个：RTE 和 MRPC。RTE 56.0 对 61.7（一个多任务训练的 BiLSTM），MRPC 82.3 对 86.0。原文把 RTE 的落后归因于训练集太小（2,490 条），并猜测多任务训练可能有帮助。
  • GLUE 总分 72.8，此前最好的多任务 BiLSTM+ELMo+Attn 是 68.9。

从这张表能读出三件事：

  • 预训练是最大的单一因素。没有预训练，CoLA 从 45.4 掉到 18.9，STS-B 从 82.0 掉到 30.9。这些任务的训练集都不大，模型只靠下游数据根本学不出语法和语义相似度。
  • Transformer 比 LSTM 强，但不是在每个任务上。平均差 5.6 个点，MNLI 上差了 8 个点（73.7 对 81.8），可 MRPC 上 LSTM 反而高一点。论文的解释是 Transformer 的结构化记忆更适合迁移。
  • 辅助 LM 损失是把双刃剑。它帮了 QQP、MNLI、QNLI、RTE，却伤了 CoLA、SST-2、MRPC、STS-B。论文的总结是大数据集受益、小数据集不受益（RTE 是个例外）。这个结论在后来的 BERT 等工作中基本被放弃，标准做法变成了微调时只用任务损失。

迁移多少层

论文还做了一个实验：只把预训练模型的前 k 层迁移过去，其余随机初始化。结论是迁移 embedding 就有帮助，之后每多迁移一层都继续提升，在 MultiNLI 上完整迁移比只迁移 embedding 最多高 9 个点。这说明预训练模型的每一层都学到了对下游有用的东西，不只是底层的词法特征。原文以曲线图给出，正文没有逐层数字，所以这里不画。

同期工作：2018 年的四条路线

2018 年一年之内，“预训练语言模型”这件事出现了四个关键工作。放在一起看，才能看清 GPT-1 到底押对了什么、押错了什么。

ULMFiT2018-01LSTM单向语言模型整体微调，配合逐层解冻等技巧6 个文本分类任务，大多数数据集上错误率降低 18–24%；只用 100 条标注就能达到从头训练 100 倍数据的效果
ELMo2018-02双向 LSTM前向、后向两个语言模型把各层表示作为特征加进已有任务模型问答、蕴含、情感分析等 6 个任务刷新纪录

ULMFiT、ELMo、BERT 的时间和数字取自各自 arXiv 摘要页。

和 ULMFiT 比，GPT-1 的思路几乎一样：预训练单向语言模型，再整体微调。区别是骨干从 LSTM 换成了 Transformer，以及处理句对、多选这类结构化输入的通用方案。ULMFiT 只做了单句文本分类，GPT-1 覆盖了推理、问答、相似度，说明“整体微调”这条路不限于分类。

和 ELMo 比，两者都用语言模型做预训练，但 ELMo 是“特征提取”，下游模型仍需各自设计；GPT-1 是“整体微调”，下游几乎不用设计。ELMo 是双向的，GPT-1 是单向的，这一点在当时看是 ELMo 占优。

和 BERT 比，有一组数字值得对一下：BERT 摘要里说 GLUE 提升了 7.7 个点、MNLI 提升了 4.6 个点，而 80.5 − 72.8 = 7.7，86.7 − 82.1 = 4.6，减去的正是 GPT-1 的成绩。也就是说，BERT 发表时的“此前最好”就是 GPT-1。BERT 沿用了 GPT-1 几乎全部的工程方案（Transformer、整体微调、特殊 token 拼接输入、只加一层），只把目标换成了双向的掩码语言模型，就拉开了 7.7 个点。这是对“单向 vs 双向”最干净的一次对照实验。

回头看，GPT-1 押对的是 Transformer 和“整体微调、少改结构”，押“错”的是单向。但单向恰恰是生成能力的前提，几年后规模变大时，这个“错”变成了优势。

影响与后续

BERT（2018 年 10 月）直接以 GPT-1 为靶子：同样是“预训练 Transformer + 整体微调”，但把单向语言建模换成了掩码语言建模，让每个位置都能看到左右两边。BERT-Base 的规模刻意和 GPT-1 对齐（12 层、768 维），就是为了在同等大小下比较单向和双向。在理解类任务上，双向赢了，此后两年 NLP 的主流几乎都是 BERT 系。

GPT-2（2019 年 2 月）没有去和 BERT 拼 GLUE，而是沿着论文零样本那一节继续走：把模型放大到 15 亿参数、换成更大更杂的网页数据，不再微调，直接用文本提示去做任务。GPT-3（2020 年）继续放大，把零样本扩展为 few-shot in-context learning。回头看，正是“单向、生成式”这个在 2018 年看来吃亏的选择，让 GPT 路线在规模变大后反超。

局限与争议

  • 仍然需要逐任务微调。零样本只是一个趋势展示，实际用起来每个任务还得有标注数据、单独训练一份模型。这是 GPT-2/3 要解决的问题。
  • 单向注意力在理解任务上吃亏。BERT 的论证就是：句子分类、问答这类任务里，每个位置看不到右边上下文是没必要的限制。GPT-2 论文自己在结论里也承认，不清楚额外的数据和容量能否弥补单向表示的低效。
  • 辅助目标的结论站不住。论文正文强调辅助 LM 损失有用，但自己的消融里去掉它平均分更高，结论只在大数据集上成立。
  • 输掉的小数据集。RTE、MRPC 上落后，说明当时这套方法对很小的训练集还不够稳。
  • “理解”这个词说得很满。GLUE 这类基准后来很快被刷到接近人类水平，社区逐渐意识到基准分数和“理解”之间有距离，评测转向更开放、更难的任务。
  • 数据来源。后来的研究对 BooksCorpus 的来源、重复内容和授权状况提出过质疑（这一点本文没有逐项核实）。在今天看来，预训练数据的来源和许可是一个独立的大问题，而 2018 年的论文对此几乎没有讨论。

和你的关系

“大底座 + 小接口”的分工。GPT-1 的结论是：通用能力放在预训练模型里，任务适配越轻越好。放到 TurboPi 上，对应的就是让云端或本地大模型负责通用理解和任务规划，机器人侧只暴露一层薄的、格式固定的接口（动作原语、传感器读数），而不是为每种任务写一套专门的逻辑。

输入改写就是你在做的状态序列化。把超声波读数、IMU 姿态、视觉检测结果拼成一条有分隔符的文本或 token 序列交给模型，本质上和图 4 是同一件事。GPT-1 的经验是：格式要固定、分隔要清楚，相似度那一招（两个顺序都跑一遍再求和）也提醒你，当输入没有天然顺序时，要么让模型对顺序不敏感，要么在格式上消除顺序。

防遗忘。如果以后在自采数据上微调小模型或 VLA，“微调时混入原始预训练目标或通用数据”是从 GPT-1 就开始的老办法，但它的效果取决于你的数据量，要自己做消融，不要默认有用。
