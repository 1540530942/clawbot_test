推测解码：小模型先猜，大模型把关Fast Inference from Transformers via Speculative Decoding

语言模型生成 K 个词要串行跑 K 次。这篇论文借用 CPU 的分支预测：让便宜的小模型先猜几个词，大模型一次并行核对。猜对的直接留下，猜错的换掉。巧妙之处在于接受规则：无论小模型多差，最终输出的概率分布都和只用大模型完全相同。

实习生和主编

主编只看一遍

主编写文章很慢，但他读得快。于是让实习生先写一段，主编看一眼。前面写得对就留下，从第一个不满意的地方开始，主编自己改一个词，再让实习生接着写。

这样主编一次能产出好多词，而最后的文章读起来和主编亲手写的一样。比喻是我们编的。真正难的一点是：怎么保证“一样”？

推测采样：为什么分布不变

我们想从大模型的分布 p(x) 采样，手里只有小模型 q(x) 的样本。规则：

  1. 从 q 采一个 x。
  2. 如果 q(x) ≤ p(x)：收下。
  3. 如果 q(x) > p(x)：以 p(x)/q(x) 的概率收下；否则拒绝。
  4. 拒绝时，从 p′(x) = norm( max(0, p(x) − q(x)) ) 重新采。
证明（附录 A.1，只要加减法）
  1. 收下的概率：q(x′) · min(1, p(x′)/q(x′)) = min(q(x′), p(x′))。
  2. 对所有 x 求和，得到总接受率 β = Σ min(p, q)。
  3. 拒绝后，从 p′ 采到 x′：p′ 的归一化常数正好是 1 − β，所以这部分概率是 (1 − β) · p′(x′) = p(x′) − min(q(x′), p(x′))。
  4. 相加：min(p, q) + p − min(p, q) = p(x′)。证毕。
数字例子（我们算的）
  1. p = (0.5, 0.3, 0.2)，q = (0.2, 0.6, 0.2)。
  2. β = 0.2 + 0.3 + 0.2 = 0.7。
  3. 小模型猜第 2 个的概率 0.6，收下 0.3/0.6，所以收下第 2 个的概率是 0.3。
  4. 剩下的 0.3 从 p′ = (0.3, 0, 0)/0.3 = (1, 0, 0) 来，第 1 个得到 0.2 + 0.3 = 0.5。和 p 完全一样。
动手玩：推测采样

三个选项。拖动小模型的分布，浏览器里真的采样 20000 次，看结果和 p 对比。这个 p 固定。

算法 1

  1. 小模型自回归地猜 γ 个词 x1..γ。
  2. 大模型一次并行跑 γ + 1 个前缀，得到 p1..γ+1。
  3. 从左到右检验，第一个 ri > pi(xi)/qi(xi) 的位置停下，前面 n 个都收下。
  4. 从 p′ 采一个词（全收下就从 pγ+1 采）。一次产出 n + 1 个，最少 1 个，最多 γ + 1 个。

所以调用大模型的次数绝不会超过原来。argmax、top-k、温度都可以写成“调整过的分布”，于是全都统一到这个框架。

能快多少

β = Σ min(p, q) = 1 − DLK(p, q)，　α = E[β]

DLK 是论文定义的距离，和总变差相同。α 就是小模型能猜对多少。如果每步的 β 独立同分布：

E(产出词数) = (1 − αγ+1) / (1 − α)
推导（等比数列）
  1. 至少产出 1 个。产出第 2 个的概率 α，第 3 个 α²……
  2. 期望 = 1 + α + α² + … + αγ = (1 − αγ+1)/(1 − α)。
  3. α = 0.8，γ = 5：(1 − 0.8⁶)/0.2 = (1 − 0.262)/0.2 ≈ 3.69。和论文表 1 一致。

再算上小模型的成本（c = 小模型一步 / 大模型一步）：

提速倍数 = (1 − αγ+1) / [ (1 − α)(γc + 1) ]　　运算量倍数 = (1 − α)(γĉ + γ + 1) / (1 − αγ+1)
动手玩：提速和运算量

这两个公式的计算器。ĉ 取和 c 相同。

代价：运算量上升，猜错就浪费了。作者的前提是有多余的算力，而大模型推理主要被内存带宽卡住。一次读权重和 KV 缓存就能算好几个位置，所以读内存的次数反而下降。

如果 α > c，一定存在有提速的 γ，至少 (1 + α)/(1 + c) 倍。

怎么选小模型和 γ

  • 小模型大小：约小两个数量级最好，兼顾 α 和 c。太大虽然 α 高，但 c 也高（下表 T5-large 反而慢）。
  • γ：数值求最优。如果有神谕能按 β 变化调整 γ，还能再快约 60%。
  • n-gram：查表，c ≈ 0。二元模型 α ≈ 0.2，也有 1/(1−0.2) = 1.25 倍。
  • 照抄上下文：摘要、改写代码、聊天里重复内容很多，匹配到前缀就抄，α 可能很高。这是提示查找解码的思路。
  • 非自回归小模型：一次出多个。
  • 甚至随机：总有一点提速，只是理论趣味。

附录要点

  • A.2 和拒绝采样的区别：拒绝采样要乘 M = max(p/q)，而且拒绝后重来。推测采样接受率是 Σ min(p, q)，高得多。
  • A.4 束搜索：小模型束宽 u ≥ w，走 γ 步，大模型并行检查 w + uγ 个候选；只要大模型的 top-w 包含在小模型的 top-u 里就接受。留作未来工作。
  • A.5 宽容度 l：比较时把 q 乘 l，接受更多，放弃严格相同。保证是：任何词被采到的概率不超过 p(x)/l。

读表时要注意的地方

  • 对比的不只是算法：表 4 里实测常常高于理论（CNNDM T5-small：理论 2.4，实测 3.1）。算法本身不可能超过理论，所以作者说有“实现优化差异”：基线 T5X 和他们的实现不一样。表 2 的倍数不纯粹来自推测解码。反过来 T5-large 的 1.7 低于理论 2.5。
  • “越尖锐 α 越高”有例外：§4.2 说所有模型都如此，但表 3 GPT-like 97M 是 0.88（t=0）对 0.89（t=1），LaMDA 2B 两者都是 0.71，一元和二元模型也相等。
  • A.5 的一处方向：论文写“p(x) ≤ l · max(p) 时接受”，按上下文应该是 ≥。写成 ≤ 就成了接受低概率的词。
  • α 的写法：推论 3.6 写 E(min(p,q))，应该是 E(Σx min(p,q))。
  • i.i.d. 是简化：真实文本有的段容易，有的段难，作者承认这是差距来源之一。
  • 只跑了批大小 1：多条并发时并行算力未必多余，下一期 vLLM 会遇到这个问题。
  • “identical outputs”：是分布相同，也就是同样的随机种子不会给出一样的结果。摘要说“identical outputs”，在 argmax 下才真的逐字相同。

这组结果怎么读（诚实版）：
  • 最重要的一条复现了，而且很干净：推测解码不改变分布。把前缀后 3 个字符的联合分布拿来比较，“推测解码和直接采样”的距离是 0.214，“两次直接采样”的距离是 0.215，二者分不开，这个距离只是采样噪声。只用小模型则是 0.618。结果是不是对的，这一条说了算。
  • 公式也对得上：温度 1 时小 MLP 的 α = 0.61，公式预测 γ = 3 时每次调用得到 2.22 个词元，实测 2.19；γ = 12 时预测 2.58，实测 2.62。收益先快后慢，上限是 1/(1 − α) = 2.59（实测略高出一点是采样波动）。
  • argmax 模式有个例外：γ = 8 和 γ = 12 的实测完全相同，两个种子也差很多（3.71 和 5.42）。我们猜是因为确定性生成很容易进入循环，只要小模型学会了循环，就总猜得中，但没有单独验证。所以这里的 α 不能代表一般情况。
  • 小模型怎么选：运算量只有大模型 3.2% 的小 MLP，温度 1 时 α = 0.61；约 18% 的中 MLP 是 0.71；二元表 0.48；一元表 0.34。多花 6 倍运算量，只换来约 0.1 的 α，要不要花取决于小模型的开销，这也是论文讨论的取舍。我们没有算墙钟时间，所以不声称具体提速倍数。
  • α 和温度的关系不单调：一元表在温度升高时 α 上升（分布变平，反而容易重合）；小 MLP 则是 argmax 时最高。它也和句子内容有关，不是模型的固定属性。
  • 宽容度是用质量换速度：l 从 1 降到 0.1，α 从 0.62 升到 0.88。这时分布不再严格等于大模型，只能在能接受近似时用。我们没有测这种近似对质量的影响。
  • 这是玩具：大小模型都是字符级 MLP。真实系统的提速还取决于硬件，这里不能回答。

一页总结

  • 一条规则：q ≤ p 就收，否则按 p/q 收，拒绝时从 max(0, p−q) 采。
  • 一个证明：min(p,q) + (p − min(p,q)) = p。
  • 一个公式：(1 − αγ+1)/(1 − α)。
  • 一个交易：多花运算量，换延迟。
  • 一个提醒：2–3 倍里混着实现差异；分布相同不等于逐字相同。
