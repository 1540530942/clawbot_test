InstructGPT：教模型听人话Training language models to follow instructions with human feedback

你问 GPT-3：“用几句话给 6 岁小孩讲讲登月。”它可能回你：“用几句话给 6 岁小孩讲讲引力。”它不是在回答，而是在续写。这篇论文让 40 个人给模型的答案排序，再把这些偏好变成训练信号。结果，13 亿参数的小模型比 1750 亿参数的 GPT-3 更受人喜欢。这条路线后来被称作 ChatGPT 背后的方法之一。

为什么 GPT-3 不听话

只会接话的人

想象一个读过整个互联网的人，但他只有一个习惯：听到一句话，就猜下一句最可能是什么。

你问他“怎么煮鸡蛋？”他想到网上的常见问题列表，于是接上：“怎么煮米饭？怎么煮面条？”

他知道的很多，但他学的目标是接话，不是帮你。论文把这叫作目标没对齐（misaligned）：预测网页下一个词，和“有用、安全地听从指令”，本来就是两件事。

论文开篇说得很直接：模型变大，并不会自动更懂用户的意图。对应的三个目标来自 Askell 等：有用（Helpful）、诚实（Honest）、无害（Harmless）。

注意“对齐”在这里有明确的含义：按用户的意图行事。论文明确说，这不是让模型符合某种普遍的“人类价值”，后面还会专门讨论对齐的对象到底是谁。

追本溯源：从打游戏到写摘要

时间工作贡献

2021Wu 等分层总结整本书，人难以直接判断时怎么办
2021Askell 等（Anthropic）有用、诚实、无害的框架和基线
2021FLAN、T0用公开 NLP 任务加指令微调，零样本也有提升
2022InstructGPT把 RLHF 用到各种真实用户指令上

依据：本论文第 2、3 节；Christiano、Stiennon、Wu、Askell 查了摘要。

缩写 RLHF 是“从人类反馈强化学习”。它早期是为了不写奖励函数也能教智能体打游戏。本文最大的贡献不是新算法，而是把这套方法用在五花八门的真实指令上，并拿它和各种基线一一比较。

三步训练

  1. SFT（监督微调）：标注员亲自写好答案（示范）。在约 1.3 万个提示上，用普通监督学习微调 GPT-3。
  2. RM（奖励模型）：让标注员给模型输出排序（约 3.3 万个提示）。训练一个模型，输入提示和回答，输出一个分数，预测人更喜欢哪个。
  3. PPO（强化学习）：把 RM 当裁判。模型生成回答，裁判打分，模型往高分方向调（约 3.1 万个提示）。

为什么不直接用第一步？人写示范很贵，而且只说了“这是一个好答案”，没说别的答案有多差。比较则便宜得多，还可以不断对模型的新输出做。第二、三步还可以循环进行。

第二步：把排序变成分数

标注员一次看 K 个回答（K 在 4 到 9 之间）并排序。排序能拆成 C(K,2) 对“A 胜 B”。论文的损失（式 1）：

loss = − E[ log σ( r(x, y赢) − r(x, y输) ) ]
r(x, y)
奖励模型给“提示 x + 回答 y”打的分。
σ
S 形函数，σ(z) = 1/(1 + e−z)，把任意数压到 0 到 1，表示“人更喜欢赢家”的概率。
两分之差
就是对数几率。差越大，模型越确定。
算一个例子
  1. RM 给赢家打 2 分，输家打 1 分。差 1，σ(1) ≈ 0.73，损失 −ln 0.73 ≈ 0.31。
  2. 如果反过来，给赢家 1 分、输家 2 分。差 −1，σ(−1) ≈ 0.27，损失 −ln 0.27 ≈ 1.31。打错了，损失更大。
  3. 只有分差有意义，所以整体加减一个常数不改变损失。论文因此用一个偏置，把人写的示范平均分调到 0。
动手玩：拖一拖两个分数

r赢 是赢家得分，r输 是输家得分。观察损失怎么变。

一个工程要点：排序产生的比较对彼此高度相关。如果拆开洗牌，每个回答会被用 K − 1 次，模型一遍就过拟合。所以论文把同一提示的所有对放进同一个批元素，也省了前向次数。另外，RM 训练只跑一遍（再多就过拟合）。所有模型共用一个 6B 的 RM，因为 175B 的 RM 不稳定，而且太耗算力。

RM 的准确度如何？用 5 折交叉验证，对没参与训练的标注员预测准确率 69.6 ± 0.9%，训练组是 72.4 ± 0.4%。而人与人之间的一致率约 73%。也就是说，这个裁判差不多和另一个人一样可靠，也一样不完美。

第三步：PPO 和 KL 惩罚

强化学习的环境很简单：给一个提示，模型写一个回答，裁判打一次分，结束。目标（式 2）：

目标 = E[ r(x, y) − β · log( π(y|x) / πSFT(y|x) ) ] + γ · E[ log π(x) ]
r(x, y)
裁判分数。
β 项
KL 惩罚：别离第一步的 SFT 模型太远。β = 0.02。这是防止钻裁判的空子，RM 毕竟不完美，追着它的最高分跑，往往得到胡言乱语。
γ 项
预训练混合：继续保留原来“读互联网”的能力。γ = 27.8（下面的“对齐税”会讲）。γ = 0 的模型叫 PPO，γ > 0 的叫 PPO-ptx。本文说的 InstructGPT 就是 PPO-ptx。

细节（附录 C）：25.6 万个回合、批大小 512、切成 8 个小批只过一遍、裁剪比 0.2、权重指数平均。每个 RL 回合配 8 个预训练样本，所以训练时间约翻倍。算力上，175B PPO-ptx 约 60 PF·天，SFT 4.9 PF·天，GPT-3 原始预训练 3640 PF·天。

占比
  1. (60 + 4.9) ÷ 3640 ≈ 1.8%。
  2. 也就是说，对齐这一步算力只占原模型的 2% 不到。但这里只算了算力，没有计入 40 位标注员的成本和试验成本。

流程上有个小的自举问题：一开始没有“听话”的模型，用户不会提交指令式的提示。所以第一批提示由标注员手写。训练出早期模型放到 API 后，再收集真实提示。论文说只用 Playground 的数据（用户会收到提示），不用生产环境的数据，并按用户或组织分割训练集和测试集（这个地方 §3.2 写用户 ID，附录 A.2 写组织 ID，并不一致）。

标注员是谁

  • 约 40 人，来自 Upwork 和 Scale AI，经过筛选：能识别敏感内容、和研究员排序一致率达 75%、敏感示范分 6/7 以上。
  • 19 人回答了问卷：男 50%、女 44.4%，东南亚裔 52.6%、白人 31.6%，菲律宾、孟加拉各 22%，美国 17%，约 74% 未满 35 岁。论文写“75%”，有小的出入。
  • 满意度：大多觉得有趣、报酬合理，约三分之一觉得重复。这是匿名问卷，不到半数回答。

一个容易忽略的设定：训练时让标注员把“有用”放第一，评测时把“真实和无害”放第一。作者解释说训练时不这样做要作很多难的设计决定，留待未来。这直接导致下面“乐于回答有害指令”的结果。

结果：人更喜欢谁

  • 一步一步好起来：GPT-3 → 精心写提示的 GPT-3 → SFT → PPO。前缀比赛也很有趣：两位作者各花一小时找最好的前缀，以 RM 分数定胜负。
  • 小模型胜大模型：1.3B PPO-ptx 的输出被认为优于 175B GPT-3。这是论文最著名的一句话：相差 100 多倍的参数，比不过一次对齐。
  • 具体方面（图 4）：更适合做客服、更能遵守明确约束、更少偏离指令、更少编造。其他类别太少见，统计上看不出差别。
  • 留出的标注员：没参与训练、也没筛选的标注员给出的结论也相似。但他们来自同一个供应商，还不足以代表更广的人群。
  • FLAN、T0：只比 GPT-3 好，和好提示的 GPT-3 差不多，低于 SFT。175B InstructGPT 对它们的胜率是 78%、79%。

  • 真实性：封闭任务（比如摘要）中幻觉率 21% 对 41%。但 TruthfulQA 的说法很有意思：引言说“约两倍”，§4.2 的人工评测说“小而显著”。致谢中感谢别人“指出自动 TruthfulQA 指标夸大了 PPO 模型的提升”。而且 1.3B PPO-ptx 其实还比同规模 GPT-3 略差。
  • 毒性：引言的“少 25%”只在加上“要礼貌”的指令时成立。去掉指令，优势消失。表 14 中 175B 无提示时 0.231 → 0.234，反而略高。
  • 被要求有毒时反而更毒：175B 从 0.285 到 0.400，6B 从 0.261 到 0.512。这是“听话”的副作用。
  • 偏见：Winogender、CrowS-Pairs 上没有明显改善。指示要尊重时，熵反而更低，表示模型更笃定，论文认为这偏向更高的偏见。

所以论文的标题是“跟随指令”，它让模型变得听话，但并不天然更善良。

对齐税

PPO 模型在一些公开任务上退步了：SQuAD、DROP、HellaSwag、WMT 翻译。论文把这叫对齐税。为了对齐损失能力，这样的方法没人愿意用。

  • 办法：训练 PPO 时混入预训练数据（γ 项）。这能大幅恢复这些任务，HellaSwag 甚至超过 GPT-3，但 DROP、SQuADv2、翻译仍略低。同时人类偏好分数基本不变。
  • 对比：把 KL 系数加大 100 倍到 2.0 也修不好，反而大幅降低验证奖励（图 34）。所以真正需要的是预训练数据的分布。
  • 训练更久：回合从 25.6 万加到 51.2 万，DROP、SQuADv2 又会降到 GPT-3 以下（图 35）。

为什么这样呢？论文没有给出机制解释。读者可以把它想成：不断只练答题，慢慢忘了原来的知识。这是我们的比喻。

到底对齐给了谁

§5.2 是整篇最值得细读的部分之一。论文点名说，它对齐的是：

  1. 标注员：主要是说英语的美国和东南亚人。彼此一致率也只有约 73%。
  2. 研究员：他们写了标注指南，还在聊天室回答边界问题。所以实际上也是 OpenAI 的偏好。
  3. API 客户：提示来自他们，而客户的利益不一定等于最终用户的利益，比如客户可能只想让用户停留更久。
  4. 等待名单上的人：早期用户从等待名单挑选，最初的种子是 OpenAI 员工，所以偏向他们的人脉。

论文的说法很克制：这篇只是证明这个方法能对齐到一个特定的参考群体，并不主张他们是正确的来源。“不可能训练一个对所有人都对齐的系统。”这句话值得记住。

亲手试：走完整条流程

我们用 NumPy 从头走了一遍。玩具世界里，有三条指令：重复、倒序、最大。“互联网”语料里有 60% 是指令后面接另一条指令（对应 GPT-3 只续写的习惯），15% 是正确答案，10% 带“坏词”，5% 先说“也许”，还有 10% 是“下一个字母”（当作公开任务，人类数据里没有）。

  1. 预训练：3000 步。
  2. SFT：只有 30 条人工示范（故意很少，因为示范最贵）。
  3. RM：每次 4 个回答排序（用我们写的“真实偏好”加噪声模拟标注员）。
  4. PPO：250 步，分别加上 KL、预训练混合和不加 KL 的版本。还训练了一个 16 维的小模型，以及一批“喜欢回答前先说‘也许’”的标注员。

2 个种子。这是我们设定的简单世界，真实偏好是我们写的函数，不代表论文结果。完整脚本在这里。

怎么读：有的现象和论文一致，有的完全不一致。

  • 一致：模型从“续写”变成“回答”。只预训练时，67% 的回答是接另一条指令，指令正确只有 16%。微调后接指令几乎消失。
  • 一致：小模型胜大模型。16 维的 PPO 模型正确率 35%，在成对比较中有 81% 胜过 32 维的只预训练模型（见图）。这和论文“1.3B 胜 175B”方向相同。
  • 一致：公开任务退化，混合能修。“下一个字母”在预训练后 100%，SFT 后 80%，PPO 后 40%，加了预训练混合的 PPO-ptx 回到 100%。这对应论文的 PPO-ptx。不过这个任务只有 5 道题，每题 20 分，数字很粗。
  • 一致：没有 KL 就崩溃。去掉 KL 后正确率只有 8%。
  • 不一致：PPO 没有胜过 SFT。这是最重要的一点。30 条示范的 SFT 已经有 91%。PPO 平均 66%，而且两个种子差别巨大：种子 1 从 97.7% 到 98.7%，种子 0 从 84.7% 掉到 32.7%。胜率也只有 35%。种子 0 的奖励模型损失在训练末尾从 0.28 升到 0.64，说明奖励模型没学好，PPO 老老实实地按错误的方向优化。这正是论文里“奖励模型并非真实偏好”的风险，只是在玩具上放大了。
  • 不一致：换标注员也没有学到新偏好。我们本想让喜欢“也许”的标注员把模型带偏。实际上“也许”的比例几乎为 0，指令正确率倒是掉到 12%。模型被带坏了，但不是往我们预期的方向。

诚实的结论：这个小世界支持“示范和预训练很有用”“约束很重要”，但不支持“强化学习一定在 SFT 之上提升”。这可能因为我们的任务太容易，SFT 已接近上限；也因为奖励模型只有 500 步、数据很少，这些我们都没有单独验证。真实分和指令正确率都来自我们写的函数，每项只有 2 个种子。

局限和争议

  • 人群很窄：40 人，以英语为主，受研究员的指令影响。大多数比较只有 1 人标注。
  • 只是偏好，不是真实：人喜欢不代表正确。模棱两可的回答可能拿高分。
  • 不解决有害问题：论文自认为最大的局限：听话，即使可能造成伤害。后续计划用拒答。
  • 评价标准有差异：训练和评测优先级不同；胜率的基线是自家 175B SFT。
  • 评测对 GPT-3 可能不公平：论文承认提示来自 InstructGPT 用户，所以另外用 GPT-3 用户的提示也测了一遍，结论相似。附录 F 用的温度也不同，这一处略不利于 InstructGPT。
  • 偏差会被裁判放大：RM 的缺点、KL 系数都是工程选择。系统钻裁判空子的问题并没有彻底解决。
  • 对滥用的提醒：§5.5 指出，更听话也意味着更容易被滥用，而通过 API 控制也带来权力集中。

一页总结

  • 一条流程：示范 → 奖励模型 → PPO。
  • 一个对比：1.3B 对齐模型胜过 175B GPT-3。
  • 一个公式：奖励减 KL 惩罚，再加预训练混合。
  • 一个代价：对齐税，要靠预训练混合减轻。
