InstructGPT：把目标换成人的偏好Training language models to follow instructions with human feedback

GPT-3 只会接着写，因为它优化的目标是“像训练文本”。InstructGPT 让人写示范、给回答排序，再用强化学习直接优化人的偏好。最有分量的结果是：参数少 100 多倍的 1.3B InstructGPT，比 175B 的 GPT-3 更受欢迎。对用户来说，目标对不对，比模型有多大更重要。

它要解决什么问题

GPT-3 很强，但它只会接着写。你问“解释一下月球着陆”，它可能续写一串类似的问题，因为这样的文本在网上很常见。想让它做事，得精心设计 few-shot 提示。它也不怎么在意真假，会编造事实，还可能输出有害的内容。

根源在于目标不对：语言模型优化的是“像训练文本”，不是“对用户有用”。这个差距不能靠继续放大模型来解决。第 7 期的 Scaling Laws 说得很清楚，放大规模降低的是损失，而损失并不是人们想要的。

InstructGPT 要做的是直接改变优化目标：让人来评判模型的回答，再把人的偏好作为训练信号。这条路线叫 RLHF，论文也有很强的对齐动机。

核心思路：三步走

第一步，SFT：让标注员针对提示写理想回答，直接微调。模型由此学会了“回答问题”这种形式。

第二步，RM：光有示范还不够，因为写一个完美回答很难，但比较好坏容易得多。标注员对同一提示的 K 个（4 到 9 个）回答排序，训练一个奖励模型来预测人的偏好。

import numpy as np

def pair_loss(scores, ranking):
    """奖励模型：K 个回答的排序拆成两两比较，做交叉熵"""
    loss, n = 0.0, 0
    for i, a in enumerate(ranking):
        for b in ranking[i + 1:]:               # a 排在 b 前面
            loss += np.logaddexp(0, scores[b] - scores[a])
            n += 1
    return loss / n, n

scores_good = np.array([2.0, 1.0, 0.0, -1.0])   # 打分和人的排序一致
scores_bad  = np.array([-1.0, 0.0, 1.0, 2.0])   # 完全相反
order = [0, 1, 2, 3]
print("K=4 个回答拆成", pair_loss(scores_good, order)[1], "对比较")
print(f"打分一致：loss = {pair_loss(scores_good, order)[0]:.3f}")
print(f"打分相反：loss = {pair_loss(scores_bad, order)[0]:.3f}")
print(f"随机猜：  loss = {np.log(2):.3f}")
for K in (4, 6, 9):
    print(f"K={K}: 一次排序相当于 {K * (K - 1) // 2} 次两两比较")

一次排序可以拆成很多对比较，这也解释了为什么标注员排序比写答案更高效。奖励模型只用 6B 大小，因为它只需要判断好坏。

第三步，PPO：用奖励模型的分数作为奖励，用强化学习继续优化。这里有个关键细节：

奖励 = RM(回答) − β · log( π(a|s) / πSFT(a|s) ) 每个 token 都计算 KL 惩罚

KL 惩罚限制模型不能偏离 SFT 模型太远。为什么要这样？因为奖励模型是不完美的，只有约 70% 的准确率。强化学习非常擅长找到漏洞，放开了优化，它就会生成一些奖励模型喜欢但人看不懂的东西。

这个现象可以用公式直接算。这种 KL 惩罚目标的最优解是 π ∝ πSFT·exp(r/β)。假设有 5 种回答，第 5 种是原来只有 2% 概率的怪回答，但奖励模型恰好给了它最高分：

为什么数据从 API 来

大部分提示来自早期 API 用户的真实请求，这和当时常用的公开基准差别很大。这也是这篇论文容易被忽视的贡献：它在优化人们真实想要做的事，而不是基准上的题目。下图可以看到，近一半的真实请求是生成类，而基准里很少有。

关键实验与结果

最令人意外的一条：1.3B 的 InstructGPT 比 175B 的 GPT-3 更受欢迎，参数少了 100 多倍。这大概是全文最有分量的一句话。它说明对用户来说，目标函数对齐比模型规模更重要。这和第 6、7 期的规模路线形成了强烈的对比。

在这个基础上，InstructGPT 也同样提升了其他能力：

指标GPT-3InstructGPT
封闭领域幻觉率41%21%
TruthfulQA 真实且有信息的回答基准约 2 倍
有尊重提示时的有害输出基准少约 25%
Winogender、CrowS-Pairs（偏见）基准没有显著改善

偏好和幻觉都改善了，但偏见基本没有变化。论文明确报告了这一点：RLHF 并不能自动解决所有问题，它优化的是奖励模型学到的那些东西。

标注一致性

训练标注员之间的一致性是 72.6 ± 1.5%，留出标注员是 77.3 ± 1.3%；奖励模型在留出标注员上的准确率是 69.6 ± 0.9%。也就是说，人和人之间也只有七成多一致，奖励模型离这个上限不算太远。这部分差距来自“喜好”本身的不确定性。

代价很低

这是另一个容易被忽视的重点：在一个已有大模型上做 RLHF，比预训练便宜得多，只要几十 PF·天。对齐这件事的成本并不主要在算力，而在高质量的标注上。

对齐税

PPO 训练后，一些基准上的表现反而下降了（SQuAD、DROP、HellaSwag、WMT 2015 法英）。论文把这称作对齐税。作者尝试增加 KL 系数，结果验证奖励明显下降，所以不是好办法。真正有效的是 PPO-ptx：在 PPO 里混入预训练时的梯度，让模型不要忘记原来的能力。这样 HellaSwag 甚至超过了 GPT-3，但 DROP、SQuAD 和翻译上的退步仍然存在。

影响与后续

  • ChatGPT 的直接前身。ChatGPT 使用了相同的方法。从这里开始，大模型真正走向了普通用户。
  • RLHF 成了标配。此后几乎所有面向用户的大模型都有类似的流程。Llama 2、Anthropic 的 HHH 都走在这条路上。
  • 人工标注的局限催生了新方法。Constitutional AI（第 18 期）用模型自己来评判，DPO 则去掉了奖励模型和 PPO。
  • 优化目标也暴露了新问题。奉承、过度含糊和假装知道，都与训练信号的设计有关。今天的研究还在持续处理这些问题。

  • 谁的偏好？标注员约 40 人，主要说英语，数据也基本是英语。论文自己说明，这些标注员并不能代表所有用户。多数比较还是只由一个标注员完成。
  • 幻觉只是减少。21% 仍然不低，而且模型仍然可能输出有害或有偏见的内容。
  • 对非英语和代码的泛化是定性的。论文只给出定性证据，且常常用英语回答非英语指令。
  • “有帮助”的目标和其他目标可能冲突。论文明确指出，训练更看重有帮助，所以模型会听从有害指令。

和你的关系

这期最值得记住的是：1.3B 对齐过的模型，比 175B 没对齐的模型更好用。放到端侧上，模型规模受限，一个认真微调过的小模型可能比一个规模更大但没有对齐的模型好用得多。SFT 这一步成本很低，建议先把常用的机器人指令和期望输出整理成数据，再配合第 12 期的 LoRA 微调。

奖励模型“会被钻空子”这个问题在机器人上更严重：VLA 或世界模型的奖励函数如果写得不好，策略也会找到意想不到的钻空子方式，而且真机上后果更大。KL 惩罚的思路可以借鉴：限制新策略不要离已验证的基线太远。这是我的类比，强化学习里类似的做法已有成熟研究，具体方案要看任务。
