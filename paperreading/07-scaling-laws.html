Scaling Laws：规模有公式了Scaling Laws for Neural Language Models

放大模型到底能换来多少？这篇论文把模型、数据和算力拉开六七个数量级实测，发现损失近似服从幂律：指数很小，但极其稳定。规模第一次变成了可以提前算账的东西，也给出了一个影响深远的判断：大模型比大数据更重要。

它要解决什么问题

2020 年初，训练大模型是一笔要仔细算的账。GPT-2 已经 15 亿参数，下一步要不要放大 100 倍？花出去的算力能换来多少损失下降？算力该用在模型上，还是用在训更多步或者更多数据上？这些问题大多还靠直觉，或者每家自己的经验。

深度学习里有很多经验规律，但当时对语言模型并没有定量的、覆盖多个数量级的测量。这篇论文想做的就是实测：把模型大小、数据量和算力系统地拉开很多个数量级，看损失到底怎么变。

为什么是这几位作者

第一作者 Jared Kaplan 是理论物理学家。这篇论文的方法很像物理：不先讲机制，先拉开尺度测量，找出幂律，再反过来做预测。作者们自己也承认，这些规律目前没有扎实的理论解释。

核心结论：损失服从幂律

只要模型、数据和算力都没有被其他因素卡住，损失（nats/token，留出集上的负对数似然）和它们都近似服从幂律：

变量公式指数常数
模型大小 NL(N) = (N_c/N)^α0.0768.8×10¹³
数据量 DL(D) = (D_c/D)^α0.0955.4×10¹³
算力（最优）L(C) = (C_c/C)^α0.0503.1×10⁸ PF·天
算力（固定 batch）同上0.0571.6×10⁷ PF·天

在对数坐标下这几条都是直线，跨越了六七个数量级。指数都很小，含义也很直白：线性地放大规模，损失下降得很慢，但非常稳定。把它代入算一下：

参数 ×10                 损失变为原来的 0.839 倍（下降 16.1%）
数据 ×10                 损失变为原来的 0.804 倍（下降 19.6%）
算力 ×10（最优分配）           损失变为原来的 0.891 倍（下降 10.9%）

每投入 10 倍算力，损失只下降约 11%。这个数字本身不大，但有两点很关键。第一，它可以预测：今天多花多少钱，能换多少提升，事先就能算出来。第二，损失的小幅下降往往对应能力的明显提升，这一点要结合 GPT-3 这种生成质量来看。

模型和数据谁先卡住

两个因素放在一起，论文用这个公式拟合：

L(N, D) = [ (Nc/N)αN/αD + Dc/D ]αD α_N=0.076, α_D=0.103

把论文表 2 的拟合值代入，画出来就是下面这张图（这组拟合和上表略有差别，论文的 α_D 在不同章节就是 0.095 和 0.103）：

过拟合基本由 N 和 D 的比例决定，而且需要的数据量增长慢于模型大小。论文给出避免明显过拟合（损失差在 0.02 内）的数据量大约是：

D ≳ 5×10³ · N0.74

这也解释了论文里把 230 亿 token 的 WebText2 当作“近似无限”的做法：对多数实验中的模型，这个数据量已经不会过拟合。

算力该怎么分

这是整篇论文最有实际价值的一节，也是后来争议最大的部分。论文估算总算力为：

C ≈ 6 · N · B · S FLOPs，N 参数量，B batch，S 步数

这和第 6 期里验算出的“每参数每 token 6 次运算”是同一件事。要在固定算力下把损失降得最低，三者应该这样分：

翻成一句话：大模型比大数据和长训练都更重要。更进一步，算力高效的训练应该在远未收敛时就停下来，这是一个反直觉的结论：

对比项（相比训到损失离收敛只差 2%）算力高效的训练
总算力少约 65%
参数量多约 2.7 倍
参数更新次数少约 7.7 倍
停在哪里比收敛损失高约 10%

大模型学得更快，所以不用训到收敛。这也是 GPT-3 的直接依据：所有规模都只训练了 3000 亿 token，175B 模型只看了每份数据几遍或不到一遍。

临界 batch

论文还测得一个有趣的量：batch 超过某个值后，再加大对收敛没有帮助。这个临界值只和当前损失有关，和模型大小无关：

Bcrit(L) = 2×10⁸ / L1/0.21 token

什么不重要

  • 形状几乎不重要。固定非词向量参数量时，改变层数、宽度、头数和前馈维度的比例，性能变化很小，长宽比可以相差约 40 倍。
  • 只有把词向量排除掉，趋势才干净。这也是公式里 N 不含词向量的原因。
  • 学习率调度影响不大。收敛时的结果基本与调度无关，但当目标是提前停止时，最优学习率会随目标损失变化。

实验怎么做的

设置数值
主要数据WebText2：2030 万文档，96GB，2.29×10¹⁰ token
模型解码器 Transformer 为主，也有 LSTM 和 Universal Transformer
规模范围768 到 15 亿非词向量参数
数据范围2200 万到 230 亿 token
上下文大多数为 1024
默认训练Adam，2.5×10⁵ 步，每批 512 条，3000 步 warmup 后余弦衰减到 0
超过 1B 参数改用 Adafactor

论文还验证了这种规律的泛化情况：在其他文本分布（书籍、Common Crawl、维基百科）上，损失也随模型变大平滑下降，只是有一个基本恒定的偏移。LSTM 的表现也服从幂律，但在序列靠后的 token 上会落后于 Transformer。

自己算一下

下面是把论文公式写成的小函数，上面的数字都是它算出来的：

def L_N(N):                 # 表 5：数据足够、训练到收敛
    return (8.8e13 / N) ** 0.076

def L_D(D):                 # 表 5：模型足够大
    return (5.4e13 / D) ** 0.095

def L_ND(N, D):             # 公式 1.5，表 2 的拟合值
    aN, aD, Nc, Dc = 0.076, 0.103, 6.4e13, 1.8e13
    return ((Nc / N) ** (aN / aD) + Dc / D) ** aD

def B_crit(L):              # 临界 batch，单位 token
    return 2e8 / L ** (1 / 0.21)

def allocate(C_ratio):      # 算力放大 C_ratio 倍时的最优分配
    return dict(N=C_ratio ** 0.73, B=C_ratio ** 0.24, S=C_ratio ** 0.03, D=C_ratio ** 0.27)

注意第二段：同一个 N，数据只有 10⁹ token 时，损失到 10¹⁰ 参数就基本不再下降。一个预训练小模型的数据预算，可以先用这个函数估一下。不过这些数字来自英文 WebText2 和 GPT-2 风格的模型，用在别的语料上只能当参考。

影响与后续

  • 规模变成了可以写进预算的东西。提前估算某次训练的成本和效果，从这篇论文开始有了依据。第 6 期的 GPT-3 只晚了 4 个月。
  • “大模型优先”主导了 2020 到 2022 年。很多大模型的配置（数据相对少、参数非常多）都能看到这个结论的影子。
  • Chinchilla（第 15 期）修正了分配结论。DeepMind 2022 年认为，参数和数据应该差不多同比例增长，很多大模型其实训练不足。指数之外，这一点也能说明外推有多危险。

局限与争议

  • 没有理论。作者自己说，他们对这些幂律没有扎实的理论解释。为什么是这个指数，并不清楚。
  • 外推的风险。论文预测规律会在约 10⁴ PF·天、10¹² 参数、10¹² token 附近失效，同时说明这个估计高度不确定。其中的 L* ≈ 1.7 nats/token 可能有一个数量级的误差。
  • 数据小的时候拟合不好。小数据集的结果偏差大，正则化和数据增强也没有专门优化。
  • 算力公式忽略了上下文。上下文很长时，这个 6NBS 的估算就不够准了。
  • 损失不等于能力。论文度量的是留出集损失，它和具体任务能力之间的关系这里没有回答。
  • 分配结论已被挑战。N ∝ C^0.73 这一条已经被第 15 期修正，所以这篇里的幂律形式比具体分配更值得相信。

和你的关系

幂律也能反过来用：缩小模型时，损失按同一条线上升。把 N 从 10⁹ 缩到 10⁸，按 L(N) 算，损失变为约 1.19 倍。这是一个不错的压缩预期，但端侧模型真正受影响的是任务准确率，这要实测。

要在 DGX Spark 上做一次小模型训练，这篇里最有用的是两条：数据量用 5000·N^0.74 估算够不够；预算有限时，优先把模型做大、提前停止，而不是把小模型训到收敛。第二条要配合第 15 期一起看，两篇论文的分配方案有差异。
