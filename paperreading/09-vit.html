它要解决什么问题

2020 年的 CV 还是卷积的天下。Transformer 在 NLP 已经全面胜出，但用到图像上有一个直接的障碍：一张 224×224 的图有 5 万多个像素，把像素当 token 算注意力，成本是 n²，根本算不动。

所以之前的尝试都在绕路：把注意力塞进卷积网络里当模块，或者只在局部窗口算注意力，或者把图像压缩后用。这些方法都还在用卷积或各种专门设计。这篇论文问了一个更直接的问题：能不能完全不用卷积，把标准 Transformer 几乎原样用到图像上？

标题 “An Image is Worth 16x16 Words” 就是答案：把图像切块，把块当词。

核心思路

这个方法简单得有些出人意料。切块相当于一次步长和卷积核都是 16 的卷积，把 token 数从 5 万多降到 196 个，这样算注意力就可行了。后面就是标准流程：线性投影、加位置向量、过编码器、取 CLS。

关键不在结构，而在数据量

CNN 里写死了两条先验：局部性和平移等变。ViT 几乎把它们都扔掉了，只有切块和 MLP 是局部的，自注意力从第一层起就是全局的。模型要自己从数据里学这些规律，所以它需要大量的数据。这篇论文真正的结论是：数据足够多，先验就不再是优势。

有位置向量和没有差约 3 个点，但 1D、2D、相对位置几乎没有差别。论文的解释是模型处理的是 14×14 的 patch 网格，不是 224×224 的像素，网格小，1D 位置也足以让模型学到邻近关系。

分辨率变了怎么办？块大小不变，块数变多，位置向量就不够了。论文的做法是按它们在原图上的位置做 2D 插值。这也是 ViT 中少数几处用到二维信息的地方。

从零实现

切块和插值这两步是 ViT 和文本 Transformer 唯一不同的地方，其余可以直接复用第 1 期的代码：

import numpy as np

def patchify(img, P):                     # (H, W, 3) -> (N, P*P*3)
    H, W, C = img.shape
    return img[:H - H % P, :W - W % P].reshape(H // P, P, W // P, P, C).transpose(0, 2, 1, 3, 4).reshape((H // P) * (W // P), -1)

def resize_pos(pos, new_side):            # 2D 插值位置向量，换分辨率微调时用
    old = int(np.sqrt(pos.shape[0]))
    g = pos.reshape(old, old, -1); out = np.zeros((new_side, new_side, g.shape[-1]))
    for i in range(new_side):
        for j in range(new_side):
            y, x = i * (old - 1) / (new_side - 1), j * (old - 1) / (new_side - 1)
            y0, x0 = int(y), int(x); y1, x1 = min(y0 + 1, old - 1), min(x0 + 1, old - 1)
            dy, dx = y - y0, x - x0
            out[i, j] = (g[y0, x0] * (1 - dy) * (1 - dx) + g[y0, x1] * (1 - dy) * dx
                         + g[y1, x0] * dy * (1 - dx) + g[y1, x1] * dy * dx)
    return out.reshape(new_side ** 2, -1)

rng = np.random.default_rng(0)
img = rng.random((224, 224, 3))
p = patchify(img, 16)
print("224×224 图像，patch 16：", p.shape)
assert (p[0].reshape(16, 16, 3) == img[:16, :16]).all()     # 第一个 patch 正好是左上角
assert (p[1].reshape(16, 16, 3) == img[:16, 16:32]).all()   # 第二个是它右边那块
E = rng.normal(0, .02, (p.shape[1], 768))
z = p @ E
print("线性投影后：", z.shape)
pos = rng.normal(size=(14 * 14, 768))
new = resize_pos(pos, 24)
print("位置向量 14×14 插值到 24×24：", pos.shape, "->", new.shape)
print("四角保持不变：", bool(np.allclose(new[0], pos[0]) and np.allclose(new[-1], pos[-1])))

论文的说法是 ViT-L/16（JFT）在所有任务上都超过 BiT-L，同时算力需求明显更低。这和当年 Transformer 对 RNN 的胜利是同一个模式：不只是更好，还更便宜。不过注意，这里的算力比较取决于训练设置，论文自己也提醒算力效率还和训练调度、优化器和权重衰减有关。

模型学到了什么

论文看了注意力距离：有些头从最底层就关注整张图，另一些头在低层保持很小的注意力距离，有点像 CNN 的局部感受野。随着层数加深，注意力距离普遍增大，后半部分大多数头都看得很广。也就是说，局部性并不是写进结构里的，模型在需要时自己学出了一部分局部性。

自监督的预告

论文也尝试了预测被遮挡 patch 的自监督方法：遮住 50%，ViT-B/16 在 ImageNet 上得到 79.9%，比从头训练高 2%，比监督预训练低 4%。这是 BERT 遮词在图像上的第一次尝试，后来的 MAE 把这条路走通了。

影响与后续

  • 打开了视觉 Transformer 的大门。DeiT 证明用好数据增强和蒸馏，只靠 ImageNet 也能训好；Swin 把窗口注意力和层次结构带回来，用于检测和分割。
  • 今天多模态的标配。CLIP（下一期）的图像编码器之一就是 ViT，LLaVA（第 20 期）的视觉模块也来自这里。
  • “切块当词”成了通用手段。视频、点云、音频频谱，甚至机器人动作序列，都能这样变成 token。

局限与争议

  • 小数据集表现差。论文自己说明，归纳偏置少，在小数据上更容易过拟合。这是在你自己的小数据集上直接训 ViT 不可取的原因，微调才是主要用法。
  • 论文的胜利依赖内部数据。最好的结果需要 JFT-300M，这不是公开数据，别人很难复现。
  • 检测和分割没有解决。论文将其列为未来工作。全局单尺度的结构并不天然适合这些任务。
  • 和 CNN 的对比有争议。后来的 ConvNeXt 用现代训练方法重做 CNN，又把差距拉回来了，说明当初很大一部分差距来自训练配方。
  • 切块是硬边界。物体正好被切开时，只能靠注意力补回来，这也是后续重叠切块等方法的动机。

和你的关系

树莓派 5 上要算的账主要是 token 数：分辨率从 224 降到 112，token 从 197 降到 50，注意力计算量约降到 1/16。vision_semantics 如果想用 ViT 系模型，先从 patch 16、低分辨率的小模型开始，再评估是否满足检测延迟要求。

你的自采数据不会有 3 亿张，所以不要从头训，用预训练模型做微调。这篇论文的数据量表，说的正是从头训 ViT 为什么不合算。
