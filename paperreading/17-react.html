这篇论文在说什么

让你算一道应用题，你可以在纸上想。但如果要回答“这家店明天开门吗”，再怎么想也没用，你必须打电话问。大模型也一样：第 13 期的思维链让它会“想”了，可它能用的只有脑子里记住的东西，一遇到不知道的就容易编。

2022 年，普林斯顿和谷歌的研究者提出 ReAct（Reason + Act，边想边做）：让模型交替做三件事，想一想、动动手、看看结果。今天的 AI 助手会自己查资料、改代码、控制电脑，用的基本都是这个循环，你现在看到的这些页面也是这样写出来的。

旧方法的问题

当时有两种做法，各缺一半：

  • 只想（思维链）：会推理，但碰不到外部世界。不知道的事情只能靠猜，还猜得头头是道。这叫“幻觉”。
  • 只做（Act）：让模型直接调用搜索等工具。它能拿到真实信息，却不写下自己为什么这样做，查几步就忘了目标，容易迷路。
生活中的类比

想象你在一个陌生的大商场找洗手间。只想不走，你在原地推理到天黑也找不到。只走不想，你可能一直绕圈。正常人是这样做的：想“应该有指示牌”，抬头看，看到牌子写着左转，想“那往左走”，走过去，再看。

核心思想：想、做、看，循环

具体做法很简单，还是靠提示：在给模型的示例里，把“想”“做”“看”都写出来，模型就会模仿这个格式往下写。论文用到的工具也很简单，查维基百科只有三个动作：

search[词]
搜索这个词，返回页面开头 5 句话；找不到就返回相近的词。
lookup[词]
在当前页面里找下一句包含这个词的话，就像按 Ctrl+F。
finish[答案]
结束任务，交出答案。

其中有个关键的设计：“想”不会改变外部世界，也得不到任何反馈，它只是写给模型自己看的。写下来有什么用呢？它会变成接下来的上下文：拆解目标、记住进度、发现搜索结果不对，就换个词再查。

动手试试：一步步看机器人怎么“边想边做”

这是我写的示例轨迹（不是论文数据），形式和论文相同。点“下一步”往下走；再点“只想不看”，体会没有观察时会怎样。

只需要很少的示例：HotpotQA 用了 6 个，FEVER 用了 3 个，虚拟家务任务 ALFWorld 每类只用 3 条示范。

用数学看看这个循环

论文的做法可以用一个简单的写法描述。普通智能体每一步从动作集合 A 里选一个动作。ReAct 把“说话”也算作动作：

新的动作集合 = A ∪ L
A
能真正影响外部的动作，比如 search、grasp。
L
所有能说出来的话，也就是“想”。说话不改变世界。
∪
并集，就是把两个集合合起来。

为什么和“多次投票”结合更好

论文还把 ReAct 和 CoT-SC 结合。CoT-SC 让模型答多次，再选最多的答案，也就是少数服从多数。它为什么有用？用概率算一下：假设模型每次答对的概率是 p，答错时答案各不相同。那么投 3 次，只要至少 2 次答对就对：

P（3 次里至少 2 次对）= 3 × p² × (1 − p) + p³
p²×(1−p)
两次对、一次错。比如“对对错”。
3
错的那次可以在第 1、2、3 次，所以有 3 种情况。
p³
三次都对。
代入 p = 0.7
  1. 3 × 0.7² × 0.3 = 3 × 0.49 × 0.3 = 0.441
  2. 0.7³ = 0.343
  3. 合计 = 0.784，也就是从 70% 涨到 78%。投 9 次的话，能到 90%。

实际效果

这一点要说清楚：在 HotpotQA 上，ReAct 单独只有 27.4，比思维链的 29.4 还低。论文给的最好方案是组合：ReAct 走不下去时切换到多次投票（ReAct → CoT-SC，35.1），或者反过来（34.2）。这也远低于专门训练的模型（67.5）。

为什么不如思维链？看看错误分析就明白了：

胡编（幻觉）0%56%

两张表分别是答错和答对样本的分类，每类各抽 50 条。

这是整篇论文最重要的一张表。ReAct 的幻觉率是 0%，思维链是 56%。代价是它的推理更容易出错（47%），因为“查”这个动作限制了思路，查到没用的东西就会乱了方寸。两者的错误类型几乎互补，这也说明了为什么组合效果好。

到了真正要动手的任务上，ReAct 优势非常明显：ALFWorld 最好 71%，Act 只有 45%，模仿学习 BUTLER 只有 37%。购物任务 WebShop 上，成功率 40.0%，Act 是 30.1%，人类是 59.6%。

影响和局限

影响：今天几乎所有“智能体”（agent）都是这个循环：LangChain 里就叫 ReAct agent，第 33 期 Toolformer 和各种工具调用也是这条路线。大模型从“回答问题的机器”变成“能干活的助手”，这是关键的一步。

局限：

  • 会卡在重复里。模型可能反复做同一个动作。作者怀疑和解码方式有关。
  • 被烂结果带偏。搜索结果没用时，后面的推理也容易跟着乱。
  • 小模型不行。提示版的 ReAct 在 8B 和 62B 模型上是四种方法里最差的，要用大模型或微调。
  • “想”不一定是真实原因。写出来的想法只是一种输出，可以帮助工作，却不能保证它就是模型决策的真实依据。这一点在第 13 期也提到过。
  • 有副作用的动作要小心。查资料查错了没关系，但机器人和删除文件这类动作做错了很难撤回。论文只测了虚拟环境，这一点是我的提醒。

和你的机器人的关系：llm_manager 可以写成这个循环：想下一步、调一个底盘或视觉工具、看传感器返回结果。比起一次规划完所有动作，这样更能应对意外。注意在树莓派上要给循环加上步数和时间限制，防止卡在重复里，同时危险动作要过规则检查。这个做法是我的建议。

一句话总结：只想会胡编，只做会迷路；想一步、做一步、看一步，模型就有了手和眼。
