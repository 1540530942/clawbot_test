ReAct：想一步，做一步ReAct: Synergizing Reasoning and Acting in Language Models

思维链让模型会写步骤，可它写的“事实”全凭记忆，错了也不知道。另一类方法让模型调用工具，可它只动手不动脑。ReAct 把两者穿插起来：想一步，做一个动作，看环境返回什么，再想下一步。今天大多数智能体都是这个循环。但要注意，在论文自己的问答实验里，只用 ReAct 其实没有赢过思维链；赢的是两者结合。

做菜的人

论文开头的例子

你在厨房做菜。切完了菜，你心里想：“该烧水了。”发现没盐了，想：“用酱油和胡椒代替。”不知道怎么和面，想：“上网查查。”

你打开冰箱看看有什么，这是动作。看到的东西又影响下一个念头。

想和做不断交替，这就是论文要教给模型的。

论文图 1 用同一道 HotpotQA 题比较这四种方式（图本身我们没有看到，下面依据 §1 和 §2 的文字概括）：

  • 只想（CoT）：不接触外界，容易编造事实、错误一路传下去。
  • 只做（Act）：搜到了资料，却难以综合出最后答案。
  • ReAct：用想法分解问题、提取要点、改写搜索词，再综合答案。

方法：把“想”也当成动作

智能体标准框架：第 t 步看到观察 ot，选动作 at。动作依赖到目前的全部历史：

ct = (o₁, a₁, …, ot−1, at−1, ot)，　at ~ π(at | ct)

难处在于，从 ct 到 at 的映射常常很隐晦，需要大量推算。ReAct 的做法只有一句话：把动作空间扩大。

Â = A ∪ L
A
原来的动作，比如搜索、走到桌子前。
L
语言空间。这里的“动作”是一段想法。
想法 ât
它不改变环境，所以没有新观察；它只更新上下文：ct+1 = (ct, ât)。

这可以理解成：模型可以在草稿纸上写字，写完再决定怎么行动。想法有很多种用途：分解目标、用常识、从观察中提取重点、记录进度、处理异常、改写搜索词、综合答案。

两种用法：

  • 问答类，稠密想法：想、做、看严格交替。
  • 做事类，稀疏想法：动作可能很多，想法只在需要时才出现，由模型自己决定。

实验用冻结的 PaLM-540B，只靠少量提示例子，不微调。这些例子由人写下自己做题时的想法。

问答和事实核查

环境：一个很弱的维基百科接口，有意如此，模拟人查资料。

  • search[实体]：返回页面前 5 句，找不到就给 5 个相近实体。
  • lookup[字符串]：页面中下一个包含它的句子，相当于 Ctrl+F。
  • finish[答案]：结束。

HotpotQA 用 6 个例子，FEVER 用 3 个。两者都只给问题，不给支持段落。

按论文自己的表，这里的结论比摘要朴素：

  • ReAct 胜过 Act：27.4 对 25.7，60.9 对 58.9。说明想一想确实有助于行动。
  • ReAct 对 CoT：FEVER 上胜，因为支持和反驳可能只差一点，需要查证；HotpotQA 上输，甚至低于什么都不做的直接回答（28.7）。
  • 都远低于监督学习：67.5 和 89.5。

错在哪里

作者从 ReAct、CoT 各取 50 条答对和 50 条答错的 HotpotQA 轨迹，共 200 条，手动分类：

  • 幻觉：CoT 答错时 56% 是编造，ReAct 是 0%。答对时也有 14% 对 6% 的“蒙对”。这是全文最漂亮的结果。
  • 推理错误：ReAct 反而更多（47% 对 16%）。结构约束降低了灵活性；还有一种常见问题：不断重复之前的想法和动作，跳不出循环。作者猜测和贪心解码有关。
  • 搜索没结果：23% 的失败来自这里，一旦搜不到有用内容，模型很难恢复。
  • 标签问题：两者都有约 28% 算错只是因为答案和标签不完全匹配。有的 HotpotQA 标签还过时了，比如一家酒店后来变大了（附录 A.2）。这说明真实准确率比表中要高。

把内外知识结合

CoT 结构好但易编造，ReAct 事实可靠但不灵活。论文用两条简单规则结合：

  • ReAct → CoT-SC：ReAct 在限定步数内（HotpotQA 7 步、FEVER 5 步）没答出，就改用 CoT 采样投票。
  • CoT-SC → ReAct：CoT 的 n 次采样中，最多的答案不足 n/2，说明内部知识不确定，就改用 ReAct。

结果：HotpotQA 最好 35.1，FEVER 最好 64.6。而且只要采样 3 到 5 次，就能达到 CoT-SC 采样 21 次的水平（图 2）。CoT-SC 投票的计算是：

为什么用 n/2 这个门槛
  1. CoT 采样 21 次，每次一个答案。
  2. 如果最多的答案只出现 8 次（少于 10.5 次），就说明模型自己都拿不准，这时应该去查。
  3. 如果某个答案出现 15 次，就相信内部知识，也省了调用工具的成本。

微调的结果

标注成本高，论文用 ReAct 自己答对的 3000 条轨迹（类似 STaR 的自举）微调更小的 PaLM-8B、62B（图 3）：

  • 只用提示时：小模型上 ReAct 最差，因为同时学想和做太难。
  • 微调后：ReAct 变成最好。微调过的 PaLM-8B 超过所有 62B 的提示方法；微调过的 62B 超过所有 540B 的提示方法。
  • 解释：微调 Standard、CoT 相当于让模型背（可能是错的）事实，而微调 ReAct、Act 教的是怎么查资料，这是更通用的技能。所以前者很快退化。

做事：ALFWorld 和 WebShop

ALFWorld：文字版家务游戏，比如把台灯下的纸检查一遍。位置超过 50 个，专家也要 50 多步。每类任务用 3 条人工轨迹中的 2 条作提示，排列得 6 组。134 个测试游戏。

WebShop：118 万真实商品、12000 条指令的购物网站，如“带抽屉的床头柜，镍色，低于 140 美元”。500 条测试。对比方法用了 1000 多条人工轨迹，甚至上万条指令训练。

人可以改它的想法

附录 A.3 有个有趣的例子：ALFWorld 中一条轨迹因为第 17 步的一个幻觉想法而失败。人只改两处想法（删掉幻觉、加个提示），整条轨迹就成功了。人不用敲几十个动作，也不用改模型参数。

论文说这是一种新的人机协作方式。它也只是一个例子，作者把系统研究留作未来工作。下面的实验里我们也测了这个想法。

读表时要注意的地方

  • “一贯胜出”：§2 的特性 C 说 ReAct “consistently outperforming baselines”。表 1 中 HotpotQA 上它低于 Standard 和 CoT。摘要和引言也主要强调结合版和 FEVER。
  • 表 5：PaLM-540B 的 ReAct 在 HotpotQA 写 29.4，但表 1 里 ReAct 是 27.4，29.4 是 CoT。可能是取样不同（表 5 只用 500 道题），也可能是抄错，论文没说。
  • 谁是第一个闭环：§4 说 ReAct 是“第一个”在闭环系统中结合推理和行动的，§5 又说 Inner Monologue 是“第一个展示这种闭环系统的工作”。
  • 表 2 的百分比：每类 50 条，每条应占 2%，所以都该是偶数。ReAct 失败一列是 47、23、0、29，都是奇数，加起来 99。可能分母不是 50，论文没说明。
  • “最好的 6 次”：ALFWorld 报告 best-of-6（平均 57），BUTLER 是 best-of-8，都是在测试集上挑。摘要的 34% 是 71 减 37，也就是两个最大值之差。
  • 引用错误：关于采样数的段落把图 2 写成图 1；讲 ALFWorld 时把表 3 写成表 4。

亲手试：真实的搜索循环

这个实验的模型真的在循环中运行：模型写下一个人名，环境立刻返回这个人的老师和城市，模型再继续写。世界很简单：12 个人，每人有一个老师和一个城市。问题形如“A 的老师的老师住哪”。

ReAct：问 A 老师 老师 住 哪 ; 2 A : J 京 ; 1 J : A 京 ; 0 A : J 京 ; 答 京 
只行动：问 A 老师 老师 住 哪 ; A : J 京 ; J : A 京 ; A : J 京 ; 答 京 
思维链：问 A 老师 老师 住 哪 ; 2 A J 京 ; 1 J A 京 ; 0 A J 京 ; 答 京 
闭卷：  问 A 老师 老师 住 哪 ; 答 京

四种方式：闭卷（直接答）、思维链（不搜，自己写出中间事实）、只行动（只搜）、ReAct（每步先写还剩几跳，再搜）。环境每次都同时返回“老师”和“城市”，所以模型必须知道该用哪个，这正是记录进度的作用。

  • 闭卷和思维链在一个固定世界上背。
  • 只行动和 ReAct 每条样本都是新世界，只能靠搜。训练时 15% 的搜索返回“空”，要重搜。

3000 步，48 维，闭卷和思维链 2 个种子，另外两种 1 个种子（原因见下），只用 1 到 3 跳训练，再测 4 跳。这里的“想法”只是数字，比论文的自由语言简单得多。这是我们的玩具实验。完整脚本在这里。

  • 能查和不能查差别巨大：换一个新世界，闭卷和思维链掉到 10%–26%，和瞎猜（6 个城市约 17%）差不多，而且两个种子的数字完全一样，因为它们只是把背下来的旧世界答案说了一遍。思维链把中间过程写得很漂亮，但事实是编的。这对应论文里 CoT 的“幻觉”，只是我们的玩具把它放大了（这些模型本来就只见过一个世界）。
  • ReAct 没有赢只行动：训练过的 1 到 3 跳两者都是 100%。没训练过的 4 跳，只行动 60%，ReAct 49%。搜索失败时两者都约 98%–99%，也没有差别。所以我们没有复现“想法带来提升”。原因不难猜：这里的“想法”只是一个数字，模型从已有的搜索记录里也能数出来；论文的想法是自由语言，能分解任务、提取信息，我们的玩具里没有这些。
  • 想法确实能当方向盘：把 2 跳问题的想法人工改成“还剩 1 跳”，34% 的情况下模型跟着只走 1 跳，高于约 17% 的瞎猜，但多数时候并不听话。这是这种格式才有的接口，只行动没有地方可以改。论文的例子只有一个，我们的数字也只说明这个玩具。
  • 种子说明：闭卷和思维链是 2 个种子。只行动和 ReAct 的第 2 个种子因内存不足被系统杀掉，这里只有 1 个种子，数字不算稳。

局限和争议

  • 单独用并不总是好：HotpotQA 就是例子。
  • 容易原地打转：重复步骤是一种典型失败。
  • 依赖工具质量：搜不到就陷入困境。这个接口是故意变弱的，真实情况下可能更好。
  • 想法可能不真实：论文认为这样更可解释。但结合第 13 期的讨论，写下的理由未必是真正原因。
  • 安全风险：论文的伦理声明指出，把模型接到能动手的环境有危险，所以实验只用了维基百科和模拟购物，也不会真的下单。
  • 长度限制：复杂任务需要更多例子，会超过输入长度。
  • 可重复性：PaLM 当时不公开，论文提供了提示和 GPT-3 代码（GPT-3 上 HotpotQA 30.8、ALFWorld 78.4）。

一页总结

  • 一个循环：想、做、看。
  • 一个公式：Â = A ∪ L，把语言也算作动作。
  • 两组结果：问答上结合 CoT 最好；做事上大胜模仿学习。
  • 一个权衡：减少幻觉，但增加了推理错误和空转。
  • 一个遗产：今天智能体的基本结构。
