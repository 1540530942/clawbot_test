选厨师的故事

评委到底要不要单独请

你想让厨师做得更合顾客口味。RLHF 的办法：先让顾客对菜两两比较，训练一个“AI 评委”；再让厨师不断做新菜，请评委打分，慢慢改进。评委和厨师都要花钱，而且评委没吃过的菜也会乱打分。

DPO 的办法：不请评委。直接拿顾客比较过的两道菜让厨师练：好的那道多做一点，差的少做一点，同时别和原来相差太远。论文证明：只要把“评委的分数”定义成“厨师现在比原来更爱这道菜多少”，两种办法目标相同。比喻是我们编的。

RLHF 的三步和麻烦

  1. 监督微调（SFT）：得到 πSFT。
  2. 奖励模型：SFT 模型生成两个回答，人选好的。假设人按 Bradley-Terry 模型选：
p(y1 ≻ y2 | x) = exp(r(x,y1)) / [ exp(r(x,y1)) + exp(r(x,y2)) ] = σ( r(x,y1) − r(x,y2) )
符号
  • x：提示。y：回答。yw, yl：胜者和败者。
  • r：奖励，也就是“有多好”。σ：把任何数压到 0 到 1 的逻辑函数。
  • πref：参考模型，通常是 πSFT。πθ：要训练的模型。
  • β：对离开参考模型的惩罚力度。

第 3 步用 PPO 最大化下面的目标（式 3）：

maxπ Ey~π[ r(x, y) ] − β · KL[ π(y|x) ‖ πref(y|x) ]

为什么要 KL 项？防止模型跑到奖励模型不准的地方，也防止只会说一句高分的话。麻烦在于：词是离散的，这个目标不能直接求导，所以用强化学习，每步都要采样。

推导：奖励换成概率

这段是全文的核心，只要会对数就能跟下来。

第 1 步：这个目标的最优解是有公式的（附录 A.1）
  1. 目标是 Eπ[ r − β log(π/πref) ]。除以 β 并变号，等价于最小化 Eπ[ log(π/πref) − r/β ]。
  2. 定义 π* = πref · exp(r/β) / Z(x)，其中 Z 让概率加起来等于 1。
  3. 代入得：要最小化 KL[π ‖ π*] − log Z。Z 和 π 无关，而 KL 最小是 0，当且仅当 π = π*。
π*(y|x) = πref(y|x) · exp( r(x,y)/β ) / Z(x)
意思很直白：在原来的概率上，按奖励乘一个放大系数。
第 2 步：把奖励写成概率（式 5）
  1. 两边取对数：log π* = log πref + r/β − log Z。
  2. 移项：r(x,y) = β log( π*(y|x) / πref(y|x) ) + β log Z(x)。
  3. 麻烦的 Z 要对所有可能的回答求和，根本算不出。
第 3 步：Z 自己消失了（式 6）
  1. Bradley-Terry 只看分差：r(y1) − r(y2)。
  2. 两个回答的 β log Z(x) 完全相同，一减就没了。
  3. 剩下：p(y1 ≻ y2) = σ( β log(π*(y1)/πref(y1)) − β log(π*(y2)/πref(y2)) )。

把未知的 π* 换成要训练的 πθ，用最大似然，就是 DPO 损失（式 7）：

LDPO = −E(x,yw,yl) log σ( β log[πθ(yw|x)/πref(yw|x)] − β log[πθ(yl|x)/πref(yl|x)] )

这就是论文标题的含义：隐含的奖励 r̂ = β log(πθ/πref)，模型自己就是奖励模型。代码（附录 B）就这么短：

pi_logratios  = pi_yw_logps  - pi_yl_logps
ref_logratios = ref_yw_logps - ref_yl_logps
losses = -F.logsigmoid(beta * (pi_logratios - ref_logratios))

这里的 log π 是整条回答的对数概率，也就是每个词的 log 概率相加。默认 β = 0.1，批大小 64，RMSprop，学习率 1e-6。摘要任务用 β = 0.5。

一个数字例子（我们算的）
  1. β = 0.5。胜者：参考模型 log 概率 −10，当前 −9。败者：参考 −8，当前 −8。
  2. 隐含奖励：胜者 0.5 × (−9 + 10) = 0.5，败者 0.5 × 0 = 0。
  3. σ(0.5) ≈ 0.62，损失 −log 0.62 ≈ 0.47。胜者还要再往上推一点。

更新到底在做什么

∇L = −β · E[ σ( r̂(yl) − r̂(yw) ) · ( ∇log π(yw) − ∇log π(yl) ) ]

括号里：抬高胜者，压低败者。前面的权重 σ(r̂(yl) − r̂(yw))：现在排错了，权重接近 1；已经排对很多了，权重接近 0。这个刹车很要紧：没有它的“朴素版”，模型会退化，附录表 3 的样例就是一直重复 “when when when…”。

附录有一处符号错误。附录 A.4 的式 21 写成 log σ(β log(yl) − β log(yw))，最后的梯度权重写成 σ(yw − yl)。这与正文式 7 和正文的梯度相反。求导验证：设 s = r̂(yw) − r̂(yl)，−log σ(s) 的导数是 −σ(−s)，也就是 σ(yl − yw)，正文是对的，附录错了。附录那个权重会在“已排对”时反而加大力度。作者提供的代码用的是 logsigmoid，没有这个问题。另外 §5.1 把“式 7”写成“式 5”，§5.2 把“式 4”写成“式 7”。

使用流程：① 用 πref 采样回答，让人选，得到数据集；② 优化 LDPO。公开数据集没有 SFT 模型时，就在胜者回答上微调一个当 πref，这样减少分布不匹配。

定理：会不会丢东西

换元有没有限制能表示的奖励？论文说没有（在 π 足够灵活的前提下）。

  • 等价类：r′ = r + f(x)，差一个只和提示有关的数。两个奖励同一类。
  • 引理 1：同类奖励给出相同的偏好（分差相同）。
  • 引理 2：同类奖励给出相同的最优策略（exp(f/β) 在分子分母上消掉）。
  • 定理 1：每一类奖励都能写成 β log(π/πref)。条件：πref > 0，β > 0。证明是减掉 β log Z。
  • 命题 1：每类里这种写法唯一，因为 π 要加起来等于 1。

§5.2 还解释了 PPO 不稳的一个原因：标准做法少了 β log Z 这一项。它不改变最优解，但少了它，策略梯度方差大。这是软价值函数，以前用学习到的基线或单样本近似。这一段是论证，没有单独实验。

注意定理说的是最优解在无限数据和任意灵活模型下的性质。现实里两者都不满足，后面会看到后果。

实验 1：情感控制，前沿（§6.1）

IMDb 影评前缀 2–8 个词，GPT-2-large，真实奖励是情感分类器。25000 个前缀，每个采样 4 条，组成 C(4,2) = 6 对，共 15 万对。扫 22 次训练，每 100 步记录奖励和序列级 KL。结果：DPO 的前沿严格胜过 PPO，甚至胜过能拿真实奖励的 PPO-GT。论文说数字在图 2，我们看不到。

读结果时要注意的地方

  • 对话实验没有真正比 PPO：他们拿到的第三方 PPO 模型连基础模型都不如，于是把 Best of 128 当作“PPO 水平的粗略替代”。这个替代是一个假设，“优于 PPO”在对话上并未直接测出。
  • HH 只评“有帮助”：数据集包含帮助和无害，GPT-4 的提示只问“更有帮助”，而且只取一轮对话。无害性没有评。
  • 评委提示是看了人的结果选的：(C) 更接近人，所以主结果用它。合理，但这是事后选择。
  • “几乎不调参”：β 在摘要用 0.5，其它用 0.1。§6.1 还扫了 4 个值。说的是没有认真搜，不是一个值通吃。
  • “significant margin”：CNN/DailyMail 的差距没给检验。而且 DPO 也只有 36%，低于参考摘要。
  • 数据不是 πref 采的：TL;DR 偏好来自另一个相似的 SFT 模型；HH 来自未知的大模型。推导假设不严格成立。
  • 基线的实现：他们为 PPO 加了奖励归一化并调参，这算诚实；但 PPO 的表现很依赖实现，换一个可能不同。
  • 论文也提示了过优化：图 3 右的轻微下降，作者自问是不是奖励过优化，没有回答。
  • 编号错误：见上方说明。

这组结果怎么读（诚实版）：
  • 表格实验是最可靠的部分：它不用神经网络，可以算到底。用 Bradley-Terry 随机标签时，DPO 收敛到理论解 π*，β = 1 时距离只有 2.4e-14。用“永远选更好的”确定标签时，KL 一路超过约束：β = 1 的理论值是 0.63，训练 40000 步时已经到 2.53（都是 2 个种子平均），而且还在涨。这是论文推导里的假设真的会起作用的例子。
  • 同样的现象在小模型上也看得到：β = 0.5 时，确定标签的结果是奖励 2.88、KL 8.7；换成 Bradley-Terry 随机标签是奖励 1.85、KL 2.3。标签越绝对，模型走得越远。
  • DPO 胜过用学来的奖励模型的 PPO：PPO β = 0.5 是奖励 1.33、KL 1.4，β = 0.1 是奖励 2.37、KL 10.5，后者还开始重复（不重复的回答降到 88%）。DPO β = 1 是奖励 2.09、KL 3.1，β = 0.5 是奖励 2.88、KL 8.7。这个方向和论文一致。不过我们的奖励模型和真实奖励的相关系数只有 0.75，这本身就给 PPO 拖了后腿。
  • 论文说 DPO 也胜过 PPO-GT，这里没有复现：PPO-GT 拿的是真实奖励，β = 0.5 时奖励 1.89、KL 1.4，而 DPO β = 5 是奖励 1.79、KL 2.2，KL 更大奖励还更低。论文的情感任务是更大的模型和数据，PPO 难训练的问题比我们这里严重得多。
  • 只学胜者的基线：奖励 1.09、KL 0.7，比 DPO 保守得多。Unlikelihood 在权重较大时（1.0）一个种子的 KL 冲到 5.6、不重复率降到 93%，但没有崩溃。这个玩具里没有出现论文说的胡言乱语，可能是模型和句子都太短。
  • β 并不总是单调地控制 KL：从 β = 0.5 往大是单调的（8.7、3.1、2.2），但 β = 0.1 的 KL 反而更小（4.7）。这些 β 下每个种子的 KL 差很多，比如 β = 0.25 是 6.1 和 12.7，所以不要过度解读。
  • 数据少时容易过拟合：只给 300 对时 KL 冲到 17，奖励却只有 1.72，而且两个种子差很远（0.79 和 2.65）。
  • 这是玩具：语料是模板化的短影评，模型只有 2 层。KL 是采样估计，噪声不小。结果只能帮助理解机制。

局限和争议

  • KL 约束只在最优解处成立：训练中并没有计算 KL。如果数据是确定性的，r 其实是无穷大，β 也拦不住。这是后来 IPO 主要批评的（依据背景知识），我们的表格实验也看到了。
  • 只用已有的回答：DPO 不采样，模型在没见过的回答上变成什么样，损失管不到。
  • 评测是模型当评委：GPT-4 不等于人。
  • 规模：论文最多 6B。之后别人才推到更大。
  • 论文自己的问题：泛化、过优化、未标注提示怎么用，都未解决。

一页总结

  • 一个换元：r = β log(π/πref) + β log Z，分差里 Z 消失。
  • 一个损失：−log σ(β(胜者比值 − 败者比值))。
  • 一个刹车：排对了权重就小。
  • 一个前提：无限数据、灵活模型、Bradley-Terry 标签。
