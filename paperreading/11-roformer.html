RoPE：把位置写成旋转RoFormer: Enhanced Transformer with Rotary Position Embedding

位置编码想要相对位置，但相对位置的方案又都很笨重。RoPE 把向量两两看作复数，给每个位置转一个角度。每个 token 只用自己的绝对位置算一次，算内积时位置却恰好抵消，只留下相对距离。没有额外参数，也不限序列长度，后来成了几乎所有开源大模型的默认选择。

它要解决什么问题

注意力对顺序没有感知，所以要把位置告诉它。但什么是“好”的位置信息？对语言来说，一个词和它前 5 个词的关系，放在句首和放在文章第 5000 个词时应该差不多。也就是说，我们真正需要的是相对位置。

当时的方案都有不足。第 1 期的正弦编码和 BERT、GPT 的可学习位置都是把绝对位置加到词向量上，相对关系要靠模型自己学。第 5 期 T5 那种相对位置确实是相对的，但要改注意力的计算，要额外的参数，还要裁剪距离，而且和线性注意力这些快速方法不太兼容。

RoPE 的作者想要的是这样一个编码：每个 token 只用自己的绝对位置独立算一次，算出来的注意力分数却只取决于相对位置。这两件事听上去是矛盾的。

核心思路：把位置写成旋转

论文从目标反推。希望对位置 m 的 q、位置 n 的 k 满足：内积只取决于 xm、xn 和 m−n。

答案来自复数。把向量两两一组看成复数，给位置 m 乘上 eimθ：

qm = (Wqxm) · eimθ kn = (Wkxn) · einθ Re[ qm · conj(kn) ] = Re[ (Wqxm) conj(Wkxn) · ei(m−n)θ ]

内积时要取共轭，所以 einθ 变成 e−inθ，两者一乘，指数就只剩下 m−n。位置被抵消得干干净净。这个矛盾就这样解决了：计算是绝对的，结果是相对的。

扩展到 d 维就是 d/2 组平面，每组用不同的频率，频率的选法和第 1 期正弦编码相同：

θi = 10000−2(i−1)/d, i = 1, …, d/2
为什么是乘法，不是加法

加法方案里，位置向量混进词向量，计算内积时会产生词和位置的交叉项，这些项和绝对位置有关。乘法方案是旋转，模长不变，词本身的信息没有被污染。只要 Q 和 K 用同样的方式转，位置就恰好抵消掉了。

实现只有几行

写成矩阵是个分块对角的旋转矩阵，但完全不用真的构造，按元素算就够了：

import numpy as np

def freqs(d, base=10000):                  # d/2 个频率
    return 1 / base ** (np.arange(0, d, 2) / d)

def rope(x, pos, base=10000):              # x: (..., d)，pos: 第几个位置
    d = x.shape[-1]
    a = pos * freqs(d, base)
    c, s = np.cos(a), np.sin(a)
    x1, x2 = x[..., 0::2], x[..., 1::2]    # 两两一组看作复数
    out = np.empty_like(x)
    out[..., 0::2] = x1 * c - x2 * s       # 乘 e^{i·pos·θ}
    out[..., 1::2] = x1 * s + x2 * c
    return out

用这段代码做验证（d=64，随机向量）：

RoPE 的分数在小数点后 6 位都不变，而正弦相加的分数随位置明显变化。这是这期最值得亲手跑一遍的结果。

我还比了一下两种写法的速度。在 512 个向量、d=512 上，每次构造完整矩阵再相乘约 150.0 ms，按元素计算约 2.94 ms，结果一致（验证通过）。这是这台服务器上的一次实测，只能看相对差距。论文给的公式 34 也是这种写法。

注意只转 Q 和 K

V 不转。因为注意力分数只用 QK 算，V 只是被取的值，不需要参与。这和正弦编码“加在输入上，一次全部影响”是不同的。RoPE 每层都要算一遍，只不过代价很低，也不需要任何可学习参数。

几个性质

方案位置怎么进入分数依赖额外参数能否外推长序列
学习式绝对位置（GPT、BERT）加到词向量上绝对位置有（序列长 × d）不能
正弦（第 1 期）加到词向量上绝对位置（靠模型自己学相对）无形式上可以
相对位置（Shaw 等、T5）注意力分数里多加一项相对位置有（距离桶 × 维度）需要裁剪距离
RoPE乘到 Q、K 上（旋转）相对位置无能
  • 相对：上面已经验证。
  • 模长不变：旋转是正交变换，所以能和线性注意力这类依赖范数的方法结合。论文讲到了和 Performer 的组合。
  • 没有额外的参数：只由公式决定，不占存储。
  • 能外推到更长的序列：因为没有可学习的位置表，遇到更长的序列直接算就行。这是能把上下文拉到很长的基础。
  • 距离越远，内积越小：这是频率选法带来的，论文称之为长期衰减。

关键实验与结果

实验规模不大，作者来自深圳追一科技，主要关注长文本中文任务。英文实验结果偏向“基本持平”：

  • 机器翻译（WMT 2014 英德）：Transformer-base 27.3，RoFormer 27.5。
  • 预训练：同样设置下，RoFormer 的 MLM 损失收敛更快（论文只给了曲线）。

长文本才是主场

作者用约 34GB 中文语料分阶段预训练，序列长度从 512 增加到 1536，然后在法律相似案例匹配上比较：

BERT 用学习式位置，最长 512，超过就要重新做位置表。RoFormer 可以直接加长，这才是 1.5 分提升的来源。

影响与后续

  • 今天的默认选择。LLaMA（第 19 期）起，大部分开源大模型都用 RoPE 或它的变体。GPT-NeoX 早就用上了它。
  • 和 KV cache 配合得很好。每个 token 用自己的绝对位置算一次，缓存下来的 K、V 不用重算，这一点对推理很重要。
  • 变长上下文。长文本微调时常用 xPos、Position Interpolation、NTK-aware 等方法调整 base，都是在这条路线上做文章。
  • 从中文社区到全世界。论文最早是苏剑林的博客文章，后来才写成 arXiv 论文。一篇实验规模不大的论文，影响力却非常大，靠的是设计本身足够好。

局限与争议

  • 实验证据比影响力弱。GLUE 有胜有负，主要的优势只在长文本任务上体现。它的普及更多靠工程便利和后续实践。
  • 序列超出训练长度后的表现不一定好。可以直接算不代表模型真的会用：高频分量可以用，低频分量很少转完整周期，外推质量要实测。这是后来出现各种 RoPE 缩放方法的原因。
  • 只解决了相对位置。有的任务确实需要绝对位置（比如“第一句话是什么”）。纯相对结构表达这种信息更吃力。
  • 每层都要算。虽然便宜，但每层对 Q、K 都要乘一遍 cos 和 sin，常常要预计算成表来提速。

和你的关系

树莓派上跑的小模型基本都带 RoPE。它的好处是不额外占参数，也不限制序列长度，但每层都有计算成本。自己写推理代码时，可以把 cos 和 sin 预计算成表，减少三角函数调用。这对控制回路里的 CPU 预算有帮助。

这个设计思路也值得记住：别在结构上硬编码你想要的不变性，而是通过一个对称性让它自然成立。IMU 或位姿数据也有类似的旋转结构，只是这是我的类比，并非论文内容。
