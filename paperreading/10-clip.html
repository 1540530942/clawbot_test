CLIP：把分类器写成文字Learning Transferable Visual Models From Natural Language Supervision

互联网上的图和文字本来就放在一起。CLIP 只学一件事：判断哪张图和哪段文字是一对。训练完后，把类别写成一句话，模型就能直接分类。它在 ImageNet 上零样本达到 76.2%，让分类器第一次可以用文字临时定义，也成了后来图文多模态的基础。

它要解决什么问题

到 2021 年，视觉分类模型已经很强，但有两个短板：贵和窄。贵，是因为监督学习要人工标注：ImageNet 雇了 25000 人标了 1400 万张图。窄，是因为模型只认训练时的类别，想认一个新类别，就要收集数据再训一遍。

而互联网上本来就有海量的图片和文字说明放在一起。不用人专门标注，文字已经描述了图的内容。能不能直接用这种“自然语言监督”学习？

这篇论文的结果是 CLIP：同时训一个图像编码器和一个文字编码器，让配对的图文靠近。训完后，类别名字写成文字，模型就能直接分类，不需要这个类别的任何训练样本。

核心思路：谁和谁是一对

任务很简单：判断哪张图和哪段文字是一对。它不用生成图也不用生成字，所以训练效率远高于生成式方法。论文对比了这种做法和早期的 VirTex、ICMLM 等方法，认为对比目标训练的效率显然更好。

batch 的大小在这里很重要。batch 里每多一张图，负样本就多一个，这个任务越来越难，学到的表示也越来越细。这也是 CLIP 用 32,768 这么大的 batch 的原因。

import numpy as np

def normalize(x): return x / np.linalg.norm(x, axis=-1, keepdims=True)

def log_softmax(x):
    x = x - x.max(-1, keepdims=True)
    return x - np.log(np.exp(x).sum(-1, keepdims=True))

def clip_loss(img, txt, t):            # img, txt: (N, d)，t: 对数温度参数
    logits = normalize(img) @ normalize(txt).T * np.exp(t)
    i = np.arange(len(img))            # 对角线才是配对
    return -(log_softmax(logits)[i, i].mean() + log_softmax(logits.T)[i, i].mean()) / 2

rng = np.random.default_rng(0)
N, d = 256, 512
t = np.log(1 / 0.07)                   # 论文的初始温度
shared = rng.standard_normal((N, d))
print(f"随机不相关：loss = {clip_loss(rng.standard_normal((N,d)), rng.standard_normal((N,d)), t):.3f}，ln N = {np.log(N):.3f}")
print(f"部分相关：  loss = {clip_loss(shared + rng.standard_normal((N,d)), shared + rng.standard_normal((N,d)), t):.3f}")
print(f"完全一致：  loss = {clip_loss(shared, shared, t):.4f}")

随机不相关：loss = 5.853，ln N = 5.545
部分相关：  loss = 0.238
完全一致：  loss = 0.0002

这个实现是对论文图 3 伪代码的直接翻译。第一行是个可以用来排查 bug 的现象：模型什么都没学到时，损失接近 ln N，这里稍高一点是因为温度放大了随机分数。训练起点如果和这个值差得很远，多半是代码写错了。

为什么温度也要学

相似度的范围是 −1 到 1，直接送进 softmax 太平了，所以要乘一个系数（即除以温度）。论文把它作为可学习参数，初值 0.07，并限制缩放不超过 100，防止训练不稳定。下图可以看出温度的影响：

零样本分类：把类别写成文字

这里的关键不只是能分类，更在于任务由文字定义。第 6 期的 GPT-3 把任务写进提示，CLIP 把分类器写进文字。想把“狗 / 猫”换成“有人 / 没人”，改两行字就行。

提示也要工程

论文没有直接用类别名，因为一个孤立的词歧义太大：“crane” 既是起重机也是鹤，“boxer” 既是犬种也是运动员。默认模板是 “A photo of a {label}.”，只这一个模板就提高了 1.3%。进一步用 80 个模板分别编码文字后取平均，又提高 3.5%，合计将近 5 个点。

这个提升可以用一个玩具实验直观地理解：把每个模板看作“真实类别方向 + 一个噪声”，平均后噪声被抵消。下图是这个假设下的模拟结果，只用来说明趋势，并不是 CLIP 本身的数字：

其中 ViT-L/14@336 是论文推荐的默认模型。训练量非常大，这也是后来开源社区要专门复现（OpenCLIP）的原因。

关键实验与结果

论文里 ImageNet 的最好成绩是 76.2% top-1、95% top-5，这相当于当时一个监督训练 ResNet-50 的水平。

零样本的 CLIP 打败人的那一行有些特殊，论文的“人类零样本”是不看任何样例只凭名字分辨宠物品种。这一项不代表 CLIP 整体超过人。

面对分布偏移

论文用 ImageNetV2、Sketch、Youtube-BB、ImageNet-Vid、ObjectNet、ImageNet-A、ImageNet-R 七个数据集测试鲁棒性。零样本 CLIP 把 ImageNet 和这些偏移数据集之间的准确率差距缩小了最多 75%。但有个反直觉的发现：

评价项（线性探针适配到 ImageNet）变化
ImageNet 准确率+9.2%（到 85.4%）
ImageNet-R−4.7%
ObjectNet−3.8%
ImageNet Sketch−2.8%
ImageNet-A−1.9%

针对 ImageNet 做适配后，ImageNet 本身涨了 9.2%，但换到其他分布反而下降。这是一个经典的取舍：越贴合一个数据集，换了场景就越脆弱。

影响与后续

  • 打通了图文两个世界。同一篇论文之后，图像生成模型（DALL·E 2、Stable Diffusion）都用 CLIP 风格的文字编码器做条件。
  • 多模态模型的视觉入口。LLaVA（第 20 期）的视觉编码器就是 CLIP 的 ViT。
  • 语义检索。用文字搜图片、搜视频帧，今天基本都是这个方法。
  • 机器人视觉。CLIPort、LERF 等工作把 CLIP 特征用于语义抓取和三维语义地图，零样本的特点让机器人能响应没有专门标注过的物体。

局限与争议

  • 细粒度和抽象任务差。论文列举了汽车、花朵、飞机型号的细分，以及数物体和判断到最近车辆的距离。这些都不是图文配对容易学到的东西。
  • 简单任务也可能翻车。MNIST 零样本只有 88%，甚至比在原始像素上做逻辑回归还差。论文推测可能和训练数据有关。
  • 离顶尖还有距离。论文估计要把算力提高约 1000 倍才能达到整体最好的水平。
  • 偏见。数据来自未经过滤的网络，论文在 FairFace 上做了偏见分析，发现结果高度依赖类别的设计方式。提示词的改动既能减轻也能放大偏差。
  • 只判断，不定位。标准 CLIP 只对整张图打分，不告诉你物体在哪里。检测和分割要另外的方法。
  • 数据重叠。训练数据和测试集有重叠，中位数 2.2%，平均 3.2%；最高的 Country211 是 21.5%，但实测只带来 0.2% 的提升。

和你的关系

vision_semantics 可以直接用这个方法做开放词表的识别：要找的物体由 llm_manager 写成文字，图片和文字走同一套相似度。新增物体不用重新训练，这和端云协同的分工很契合：云端算文字向量，端侧只需要跑图像编码器，甚至可以把文字向量缓存下来。

要注意两点。论文明确说计数和距离判断不行，所以这类判断交给超声波和 IMU，不要交给 CLIP。另外，提示词要按真实场景写：车载摄像头视角下，“a photo of a cup” 可能不如 “a cup on the floor, seen from a low robot camera” 合适，这是我的建议，需要实测，可以用模板集成来提高稳定性。
